Tools – Favourites at the top

Follows the Tools card order (tasks/tools-card-order-todo.html, commit c4e1be60). Feature doc: docs/features/tools-card-order.md.

Why

The tools a beekeeper uses most change with the season. Moving cards within a section is not enough. Moving them into other sections would put cards under headings they do not belong to. So the beekeeper stars tools instead, and starred tools sit in a Favourites section at the top of the page (your decision, 06/11/2026).

What the code does today

  • profiles.tool_order (jsonb list of ids) holds the order within each section. NULL means the standard order.
  • Arrange mode is a one-column list with up and down arrows per tool, plus Save order, Cancel and Reset to the standard order.
  • The helpers in src/lib/tool-order.ts sort and move tools. A tool missing from the saved order goes to the end of its section.

How it will work for the beekeeper

  1. Star a tool. In arrange mode each row gets a star button (48px) next to the arrows.
    • Screen readers hear "Add Feeding Calculator to favourites", and "Remove … from favourites" once it is starred.
    • A starred tool shows a filled green star, because selections are green.
  2. Favourites is the first section in arrange mode.
    • Starring a tool moves it to the end of Favourites. The arrows order it within Favourites.
    • Removing the star moves the tool back to the end of its own section.
    • A tool is never in two places, so the page does not get longer.
    • While Favourites is empty, arrange mode shows "Tap the star on a tool to add it here."
  3. On the normal page Favourites is the first section, with the same cards as everywhere else. With no favourites the section is not shown, and the page looks as it does today.
  4. Reset becomes "Reset to the standard layout". It clears the favourites and restores the standard order. It still needs Save.
  5. Save, Cancel, the saved message, the error message, the time limits and the screen reader announcements all work as now. Starring is announced too, for example "Feeding Calculator added to favourites".
  6. On a phone the row is narrower with three buttons, so the small tool icon in arrange mode is hidden below the sm width to give the name room.

Technical changes

  1. Database (Supabase MCP migration, plus a file in supabase/migrations):
    • A new column, profiles.tool_favourites jsonb. It holds the starred tool ids in their Favourites order. NULL means no favourites.
    • The same check as tool_order: a list of at most 50 entries.
    • The same column grant for SELECT. Then run the advisors.
    • tool_order is unchanged and still holds the order within the sections.
  2. src/lib/auth.ts: add tool_favourites to PROFILE_COLUMNS.
  3. src/lib/tool-order.ts: one new pure helper, withFavourites(sections, favourites, name).
    • It returns a Favourites section first, in the saved order, followed by the sections with the starred tools taken out.
    • Unknown and repeated ids are ignored.
    • The Favourites section is then just another section, so the existing moveTool and toolOrderIds work on it unchanged.
  4. src/app/dashboard/tools/page.tsx:
    • Read both columns.
    • The grid and the arrange draft are built with withFavourites. The grid hides an empty Favourites section.
    • A star toggle in arrange mode.
    • One save writes both columns. Favourites becomes NULL when empty. The section order becomes NULL when it matches the standard order with the favourites taken out.
    • Reset clears the favourites.
  5. Tests: extend tests/lib/tool-order.test.ts for withFavourites (for you to run).
  6. Docs: tools-card-order.md and tools-card-grid.md.

Not changed

  • The tools themselves, their names, links and panels, and the ?section= links.
  • The standard sections and their names.
  • Navigation.

Review

Built as planned, in five files plus the migration.

  • Database (live, and in supabase/migrations/20261106130000_profiles_tool_favourites.sql):
    • profiles.tool_favourites jsonb, with the same check as tool_order.
    • The SELECT grant is in place, and UPDATE is covered by the existing table grant.
    • The advisors show nothing new.
  • src/lib/tool-order.ts: two new pure helpers.
    • withFavourites puts Favourites first and takes the starred tools out of their sections.
    • toggleFavourite stars or unstars a tool. Starring moves it to the end of Favourites; unstarring moves it to the end of its own section.
    • The existing moveTool orders Favourites like any other section.
  • src/app/dashboard/tools/page.tsx:
    • Both columns are read on load.
    • Favourites is section 0 in the grid and in arrange mode.
    • Each row has a 48px star button with a filled green star when starred.
    • The hints for empty sections are in place, and the grid hides empty sections.
    • One save writes both columns.
    • Reset clears the favourites and becomes "Reset to the standard layout".
    • The intro line in arrange mode now mentions the star.
    • The tool icon is hidden in arrange mode on phones.
  • src/lib/auth.ts: tool_favourites added to PROFILE_COLUMNS.
  • Tests: tests/lib/tool-order.test.ts has new cases for withFavourites and toggleFavourite (not run, for you to run).
  • Docs: tools-card-order.md rewritten for favourites, and tools-card-grid.md updated.
  • Deviation from the plan: the star button does not use a pressed state. Its label changes instead, from "Add … to favourites" to "Remove … from favourites". A changing label together with a pressed state would be read twice and is not recommended.
  • Checks: type check clean, lint clean on the changed files. No build or tests run.
  • QA audit: two Medium, both fixed. No Critical or High.
    • Accidental double tap: starring removes the row, so the next tool slides under the finger. A quick second tap (gloves, a shaky hand) would star that one too. A star tap within half a second of the previous one is now ignored.
    • Page jump: putting keyboard focus back on a starred tool scrolled the page up to Favourites, which made starring several tools further down tiresome. Focus now returns without scrolling. Screen readers still hear "… added to favourites".
  • Low: an older copy of the app still open on another device ignores favourites until it reloads. If it saves an order, the favourites are kept.

Tested by you on 06/11/2026: all good.

Batch 44: Reports and Mel

Status: Implemented 29/10/2026, waiting for your test. This is Phase 2 fix batch 31. It covers the open Medium findings in chunk 9b (reports and Mel): C9b-08, 09, 15 to 19 and 21 to 27, plus a few cheap Low ones the agents found along the way. Three agents checked each finding against the code and the live database (counts only). No database change.

A. Reports: C9b-08, C9b-09

Failed loads show as "no data": in all 7 reports a database error is dropped and the report says, for example, "No varroa treatments found". On the DAFM compliance report that reads like a clean record when nothing was loaded. If the connection drops mid-load the spinner stays on for good. An older, slower answer can also replace the report for the filter you just picked.
  • useReportsData.ts: a failed query now raises an error instead of returning an empty list.
  • Each report: a cancel flag so only the latest load counts, the spinner always stops, and a clear "Couldn't load this report. Check your connection and try again." message. Copies the pattern already used in the queen report tab.
Varroa average (Low): checks with no infestation rate count as 0%, pulling the average down. Only checks with a rate are averaged.

B. Mel finds the right record: C9b-15, C9b-24, C9b-21, C9b-27

C9b-15, "hive 1" answered with Hive 12: Mel looks up hives, queens, batches, colonies, nucs and containers with a "contains" search and takes whichever row comes first. 78 of 330 hives have a number that sits inside another hive number in the same account, so asking about Hive 1 can return Hive 10 or 12. One shared lookup replaces the 8 copies: an exact match first; if there is none, a partial match only when it is the only one; if several fit, Mel asks "Which one: Hive 10 (Home apiary) or Hive 12 (Bog road)?".
C9b-24, "not found" versus "database error": asking for a container or batch that doesn't exist says "a database error occurred", and a real database failure on a hive lookup says "Hive not found". The lookups now tell the two apart.
C9b-21, dead colonies still "in" their hive: a colony marked deceased, swarmed, sold and so on is still reported as living in its last hive, and a removal on the same day is missed. Mel now says "last colony C3, deceased; no living colony recorded". All 22 colonies are active today, so nobody has seen it yet.
C9b-27, "recent activity" isn't recent: the five "latest" inspections and treatments are whichever rows come back first. They're now sorted newest first.

C. Mel's questions and answers: C9b-16, C9b-17, C9b-19, C9b-23

C9b-16, odd numbers from the model: limits and day counts accept negative, zero, decimal or huge values ("no disease signs in the last -5 days"; years of scale data in one go). A shared bounded number rule: limits 1 to 100, days 1 to 365, scale days 1 to 30. A number sent as text ("30") is accepted.
C9b-16, the "year" rule: the router is told to always add a year, but most tools don't take one, so it's silently dropped and "best hives in 2024" is answered with all-time figures. The router now sees each tool's parameter names and only adds a year where the tool accepts it.
C9b-17, the tool router: it runs at a creative setting (0.7) with up to 1,000 words of output and no JSON mode, then strips code fences by hand. Now: setting 0, JSON mode, 300 tokens, and the answer's shape is checked. A tool name like "constructor" can no longer slip through as a "found" tool.
C9b-19, failures passed as data: a failed lookup ("Error executing getHives") is handed to the model as if it were your records, so it may repeat that text or make something of it. A failure now gets a fixed instruction ("the lookup failed; ask the user to try again"), and the miss is logged. Six tools that ignored errors and reported zeros (activity summary, hive timeline, compare hives, traceability summary, two scale tools) now report the failure.
C9b-23, "low stores": the keyword "low" also matches "flow", "slow", "below" and "yellow", and "light" matches "flight". Whole words only. Also, an old "low stores" inspection still flagged a hive whose latest inspection was fine; only the latest inspection counts now.

D. Cost: C9b-18

Three model calls per data question (classify, pick a tool, answer). Merging them is a big rewrite with a real risk of Mel misrouting questions, so I'd do the cheap parts:
  • The router change above (shorter, fixed output).
  • When no tool fits, Mel replies with a fixed message instead of a third call: "I don't have that information in your records yet. I've noted the question so we can add it."
  • The route keeps 6 history messages, not 20; only 6 were ever used.

E. Who's included: C9b-22

Missing filters: "colony in hive X" only looks at hives you created, so it misses team apiaries. "Tasks for hive X" and a colony's child colonies have no owner filter. They get the same rules as their sister tools.
Decision 1: team hives. "Hives needing inspection" includes team apiaries, but "hives needing treatment", apiary stats and hive overview only include them when asked. Done: team hives are included by default everywhere (you approved), as on the Hives page. Scales stay your own only: Mel reads scales with your own BEEP or Wolf account, so it can't read a team-mate's scale. Asking about a team hive's scale will say so, instead of trying with the wrong account.

F. The chat window: C9b-25, C9b-26

C9b-25, errors: a server timeout shows "Unexpected token '<'" and a dropped connection shows "Failed to fetch". Now these show friendly messages, for example "Mel is busy, try again in a moment" (429), "Mel couldn't answer, try again" (server error) or "No connection". A 70-second time limit stops a request hanging. A double tap can't send twice (the shared submit lock). A question that failed is left out of the history sent next time.
C9b-26, accessibility: screen readers aren't told it's a dialog, and new replies and errors aren't announced. Escape doesn't close it, and focus doesn't move in and back. The typing box is 14px (iPhones zoom in), and the times under messages are 12px. Now it uses the shared dialog hook, announces replies and errors, has a 16px typing box and 14px small text.
Decision 2: Mel on a computer. On phones Mel covers the page and a tap outside closes it. On a computer the page behind stays clickable. A proper dialog keeps keyboard focus inside Mel, which clashes with a clickable page. Done: the same as on phones (you approved). A click outside closes Mel, and the conversation is kept when you reopen it.

G. Small extras (Low)

Harvest totals in Mel read the unit through the shared harvestWeightKg, so pounds aren't added as kilograms (all 84 harvests are kg today). The harvest summary groups by hive, not by hive number, so two "Hive 3"s in different apiaries no longer merge.
"This year" uses the Irish date in two harvest and traceability tools. The intent label the model returns is checked against the four allowed values. Logging a missing-tool question is awaited and its error is read.
Left as they are: the duplicated helpers across Mel's tool files, a circular import that works, and loose types in the report table. These are tidy-ups with no bug to fix, and they would add risk to this batch.

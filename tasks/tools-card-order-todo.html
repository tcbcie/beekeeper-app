Tools – let each beekeeper arrange the cards

Feature plan: docs/features/tools-card-order.md. Page: src/app/dashboard/tools/page.tsx.

What the code does today

  • The cards come from a toolCategories list written inside the page component: four sections (Calculators, Hive Health, Business, Utilities) and 12 tools in a fixed order. Nothing else in the app uses that list.
  • No reorder feature exists anywhere in the app, so there is no pattern to copy. @dnd-kit/core is installed (apiary map only); the sortable add-on is not.
  • Per-user settings live as columns on profiles (the enable_* switches). There is no preferences table. Browser storage (usePersistentState) is cleared on sign-out and is per device.
  • No tests cover the Tools page.
  • docs/features/tools-card-grid.md is out of date: it misses the TBR Swarm Planner.

How it will work for the beekeeper

  1. Next to the intro line, a new Arrange tools button (48px, neutral tone, up-down arrow icon).
  2. Tapping it switches the page into arrange mode:
    • The grid becomes a single-column list on every screen size, so "up" and "down" mean exactly that.
    • Each row shows the tool's icon and name, with two 48px buttons: Move up and Move down (screen readers hear "Move Feeding Calculator up"). The top row's up button and the bottom row's down button are disabled.
    • Cards do not open tools while arranging.
    • A short line explains: "Use the arrows to change the order. Tap Save order when you are done."
    • At the bottom, in thumb reach: Save order (primary, green), Cancel, and a quieter Reset to the standard order.
  3. Save order writes the order once, shows "Tool order saved" and returns to the normal grid in the new order. If the save fails, it says "Could not save the tool order. Check your signal and try again." and stays in arrange mode, so nothing is lost.
  4. Cancel drops the changes. Reset puts the draft back to the standard order (still needs Save).
  5. Arrow buttons, not drag and drop: they work with gloves and one hand, need no new library, and meet WCAG 2.5.1. Drag could be added later as a shortcut.

Technical changes

  1. Database (Supabase MCP migration, plus a SQL file in supabase/migrations):
    • profiles.tool_order jsonb (a list of tool ids), nullable. NULL means the standard order. Built as text[] first, then changed to jsonb with your OK, because the profile data export can only restore lists into jsonb.
    • A check that keeps it to a list of at most 50 entries.
    • GRANT SELECT (tool_order) to anon and authenticated (profiles has column-level SELECT). Check the UPDATE grant covers it too.
    • Not a privileged column, so the guard trigger is untouched. Run the security advisors afterwards.
  2. src/lib/auth.ts: add tool_order to PROFILE_COLUMNS and the profile type.
  3. New src/lib/tool-order.ts (small, pure functions):
    • applyToolOrder(categories, savedOrder): sorts each section's tools by the saved list. Tools missing from the list (a tool added in a later release) keep their standard place at the end of their section. Unknown ids in the list are ignored.
    • moveTool(order, id, direction): swaps a tool with its neighbour in the same section.
  4. src/app/dashboard/tools/page.tsx:
    • Move toolCategories out of the component to a module constant (it never changes).
    • After the user id is known, read tool_order from the user's own profile. If the read fails, show the standard order (the page still works).
    • Arrange mode as above, with the save behind useSubmitLock and a .select('id') zero-row check. Saving the standard order writes NULL, so future new tools land where we place them.
    • Card rendering and the tool panels are unchanged.
  5. Test: a small unit test for tool-order.ts (for you to run).
  6. Docs: new docs/features/tools-card-order.md; update tools-card-grid.md (arrange mode, and the missing TBR card).

Decisions (both accepted as recommended, 06/11/2026)

  1. D1 – Where can a card move?
    • Recommended: within its own section (e.g. put TBR first in Hive Health). Sections keep their meaning and the list stays short to arrange.
    • Alternative A: within sections, and move whole sections up or down (e.g. Hive Health above Calculators). A little more code and a second set of arrows.
    • Alternative B: drop the sections and make one free list of all 12 tools.
  2. D2 – Where is the order kept?
    • Recommended: on the account (the new profiles column). It follows the beekeeper from phone to computer, survives sign-out and iOS clearing storage.
    • Alternative: on the device only (browser storage). No database change, but it is lost on sign-out and differs per device.

Not changed

  • Which tools exist, their names, descriptions, icons and links.
  • The ?section= links from other pages.
  • Navigation (sidebar, bottom bar, More drawer).

Review

Built as planned, with one change: the column is jsonb, not text[]. Six files plus the migration.

  • Database (live in Supabase, and in supabase/migrations/20261106120000_profiles_tool_order.sql):
    • profiles.tool_order jsonb, with a check that it is a list of at most 50 entries.
    • Column SELECT granted to anon and authenticated. UPDATE was already table-level and limited to the user's own row.
    • The security advisors show nothing new.
    • The first version was text[]. The data export writes lists as JSON text, so a saved order would not have restored. The switch to jsonb converted the empty column in place, because dropping it was declined. The live database and the migration file match.
  • src/lib/tool-order.ts: four small pure helpers.
    • Check the saved value.
    • Sort each section.
    • Move a tool within its section.
    • List the ids.
    • Tools not in a saved order (new ones) stay at the end of their section, and unknown ids are ignored.
  • src/app/dashboard/tools/page.tsx:
    • The card list moved out of the component, unchanged, as TOOL_CATEGORIES.
    • The grid shows the beekeeper's order.
    • "Arrange tools" opens a one-column list with 48px up and down arrows. The arrows at the ends are faded and disabled.
    • Save order (56px, green), Cancel, and Reset to the standard order.
    • Screen readers hear each move, and keyboard focus stays on the moved tool.
    • The tool panels and the card design are unchanged.
  • src/lib/auth.ts: tool_order added to PROFILE_COLUMNS.
  • Test: tests/lib/tool-order.test.ts (not run, for you to run).
  • Docs: docs/features/tools-card-order.md (new) and tools-card-grid.md, which now also lists the TBR Swarm Planner.
  • Checks: type check clean, lint clean on the changed files. No build or tests run.
  • QA audit: one High and two Medium, all fixed.
    • High: the first version held the whole page until the saved order arrived. On weak signal that could keep every tool, and links such as GDD, behind a spinner. Now tools open at once. Only the card grid waits, for at most 5 seconds, then shows the standard order.
    • Medium: the save had no time limit, so "Saving…" could hang with every button locked. It now gives up after 10 seconds with "Could not save the tool order. Check your signal and try again." and stays in arrange mode.
    • Medium: if the browser's Back or Forward opened a tool during arranging, the arrange instructions showed above that tool. They now show only on the card grid.
    • No Critical.
  • Low:
    • Teammates who can already read a profile can also read its tool order. That is harmless.
    • An admin impersonating a user changes that user's order, the same as the other profile settings.
    • Not part of this feature: the data export already writes inspections.image_urls (a text[]) as JSON text, so that column does not restore from an export.

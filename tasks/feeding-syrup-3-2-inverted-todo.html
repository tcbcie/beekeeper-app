Feeding: 3:2 Syrup and Inverted Flag

Request

  1. Add a Sugar Syrup (3:2) feed type.
  2. Add a checkbox that records whether the syrup was inverted.

Findings

  • Feed types are not hard-coded. They come from the live DB: dropdown_values in the feed_type category. Today the order is 1:1 (1), 2:1 (2), Fondant (3), and so on.
  • feedings has no column for "inverted" yet.
  • Feedings are written in two places: the Records form (FeedingForm plus handleFeedingSubmit in records/page.tsx) and the bulk Record feeding modal on the Hives page (BulkFeedingModal, whose values are spread straight into the insert).
  • Feedings are shown in FeedingCard (Records) and in the hive detail page's feeding list.

Plan

Database (via MCP)

Insert the Sugar Syrup (3:2) dropdown value between 1:1 and 2:1 (ordered by strength: 1:1, 3:2, 2:1) and shift the later display_order values up by one.
Migration: ALTER TABLE feedings ADD COLUMN syrup_inverted boolean NOT NULL DEFAULT false. Existing rows become "not inverted", and the existing RLS policies already cover the new column.

Code

types/records.ts: add syrup_inverted: boolean to Feeding.
FeedingForm.tsx: add an "Syrup inverted" checkbox (48px touch target) that appears only when the feed type is a sugar syrup. It resets to unticked if the type changes to something else.
records/page.tsx: include syrup_inverted in submitData and in the new-feeding default.
BulkFeedingModal.tsx: the same checkbox, also shown only for sugar syrups, added to BulkFeedingValues. The Hives page insert picks it up through the spread, so no change is needed there.
FeedingCard.tsx: show Inverted: Yes when the flag is set.
Hive detail feeding list: show "(inverted)" next to the feed type when the flag is set (add syrup_inverted to HiveFeeding).

Docs and QA

Add docs/features/feeding-syrup-3-2-inverted.md.
Run the qa-engineer audit on the change.

Follow-up: AI assistant

src/lib/ai/tools/feeding.ts (getFeedingHistory): select syrup_inverted and report the type as e.g. "Sugar Syrup (3:2) (inverted)".
src/lib/ai/tools/hives.ts (hive timeline): the same "(inverted)" suffix on feeding entries.
Related bug in the same lines, fixed: both tools build the amount as `${quantity} ${unit}`. Quantity is optional, so a feeding without one reaches the assistant as "null L". The proposed fix is to report "not recorded" instead.

B. Raw IDs sent to Mel (C9b-07)

getHiveOverview sent colony_id (a UUID). Fix: send the colony number instead, using an embed that names its foreign key.
getRearingBatchDetails sent mother_queen_id (a UUID, from select('*')). Fix: send the mother queen's number, from an explicit select with a named embed.
Scales fall back to the maker's device ID when unnamed. Fix: show "Unnamed scale".

C. Reports

C9b-04, frozen dates: the six reports save their dates on the first visit, so "last year" never moves forward. A week later the DAFM report silently drops that week's treatments. Fix, in useReportFilters only: for the preset periods (all, 3 months, 6 months, 1 year), work the dates out fresh each time from a new getPresetRange() in date-utils.ts. Only "custom" keeps its saved dates.
C9b-05: Varroa Monitoring with "All hives" ignored the apiary filter. Fix: filter by the apiary through the hive join, as the DAFM report already does. Archived hives' history stays in.
C9b-06: archived hives, and now also varroa checks, are saved with a time, but the end date was compared as midnight, so anything from the last day was missing. Fix: .lt(column, nextDay(endDate)) at both places.

D. "Today" in Irish time (C9b-20)

Mel runs on Vercel, which uses UTC. Add todayInDublin(), addDaysISO(), and corrected daysUntil/daysSince (they compare calendar days in Europe/Dublin) to src/lib/ai/tools/utils.ts. formatDate also uses Dublin time. Then use them in the tasks, queens, analysis, feeding and inspections tools.
getUpcomingBatchEvents also dropped events due today. It now compares calendar dates.
The report pages' "today" uses the existing local-date helper, through getPresetRange() from part C.

What the investigation established

Plan

1. Lock down the three email functions and remove the key from the trigger (High)

Generate a random webhook secret locally (never printed) and store it as an edge function secret.
notify-admin-new-user: accept the call only with the matching x-webhook-secret header, and escape the name and email in the email body. Redeploy, and put the source in the repo.
Recreate the notify_admin_new_user trigger so it sends that secret instead of the service-role key.
send-team-invitation and send-rearing-group-invitation:
  • Require a logged-in user.
  • Load the invitation by its ID and check that the caller sent it and that it is pending.
  • Take the recipient, team or group name and inviter name from the database, ignoring the request body.
  • Escape all text.
The app keeps sending the same request, so no app change is needed. First pull the rearing-group function's deployed source into the repo; it is currently missing.
/api/crm/invoice-email: escape the seller name and order number in the HTML.

2. Hide the scale tokens (High, option A)

Database: withdraw table-wide read access on profiles from app users, then grant read on every column except beep_api_token and wolf_api_token. The server-side scale routes and the AI tools use the service role and are unaffected.
hives/[id]/page.tsx and scales/page.tsx: decide "connected" from beep_connected_at / wolf_connected_at.
src/lib/auth.ts and profile/page.tsx: replace select('*') with the explicit column list.

3. User search and batch feedback (High, Medium)

search_users_for_distribution: require 3+ characters and return a masked email. Same columns, so no app change is needed beyond raising the search minimum from 2 to 3 characters.
get_batch_feedback_summary/details: only answer for the caller's own ID.

4. Logged-out decline (Medium bug)

Two small functions, decline_team_invitation(id) and decline_rearing_group_invitation(id), which decline only a pending, unexpired invitation. Swap the single update call in the 2 decline pages.

5. Deleted-account check (Low)

Replace the "anon can read deleted profiles" rule with a yes/no function, is_deleted_account(email). Swap the one query on the login page.

6. Rotate the service-role key (you, guided)

After step 1, I research the current Supabase steps and write you a short checklist covering the Vercel env vars, local .env files, the contributor env file and the embed widget. You do the rotation in the dashboard.

7. Verify and document

Rolled-back behaviour tests as real users and as anon; advisors; ESLint; type-check; the qa-engineer audit.
Docs: this plan in docs/features/security-hotfix-batch2-plan.md, the findings register, and a memory note about the profiles column grant.
Commit and push the code only. The audit docs stay local until rotation is done, then everything is committed.

Review

  • Email functions (live):
    • Both invitation functions now require the signed-in inviter and take every detail from the database. A live call with the public key gets 401, so the phishing relay is closed.
    • The admin-alert function accepts only the webhook secret: live checks give 401 without it and accept it with it.
    • The trigger no longer contains any JWT.
    • The invoice email escapes its text.
  • Scale tokens (live): app users and anon can no longer read beep_api_token/wolf_api_token. The app reads profiles through PROFILE_COLUMNS and decides "connected" from *_connected_at. The order was additive migration, then code deploy, then lockdown, so production never broke.
  • Search, feedback, decline, deleted check (live):
    • Search needs 3+ characters and matches a name fragment or a complete email, with masked results. I tightened this from your B2 answer so addresses can't be rebuilt from fragments.
    • Feedback answers only for your own ID.
    • Declining works while logged out.
    • The deleted-account check is yes/no.
  • Checks: rolled-back tests for every path, live permission checks, and advisors (nothing new). ESLint is clean and there are 0 type errors in src/. QA found no Critical or High issues. I also fixed a hidden type error: UserProfile.updated_at pointed at a column that doesn't exist.
  • Step 6 changed after research: Supabase no longer allows rotating the legacy JWT keys, and they stop working at the end of 2026. The real fix is migrating to sb_publishable_/sb_secret_ keys and then deactivating the legacy keys. That becomes batch 3.
  • New finding while researching (SEC-H8): weekly-email-digest and task-event-reminders accept the public key and return the email addresses they sent to. That is not yet fixed and is awaiting your decision.

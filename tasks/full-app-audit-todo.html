3.1 Phase 1: Security audit

Suspected issues to verify first (none confirmed yet):
  1. auto-accept-invitations edge function: verify_jwt=false and no secret check in the repo source, so a forged request might be able to join someone else's team.
  2. SECURITY DEFINER functions that take a p_user_id without checking auth.uid(): get_dashboard_overview, get_recent_activity, get_batch_feedback_*, get_user_email, lookup_user_by_email, get_recipient_*, get_app_statistics.
  3. profiles: users may be able to update their own subscription_expires_at/is_active. "Related" users may be able to read BEEP/Wolf tokens, and anon can read deleted profiles.
  4. team_invitations and rearing_group_invitations are readable by anyone (USING true for the public role), which exposes invitee emails.
  5. registration_codes is readable by every logged-in user, and three admin policies compare against lowercase 'admin', so they never match.

1A: Database (Supabase MCP, read-only SQL)

Verify suspicions 2–5 above with read-only queries (policies, grants, function bodies). All confirmed, see docs/features/full-app-audit-report.md (SEC-C1, C2, H2–H4, M1).
Draft the per-table access map (D5) and review all 78 tables' policies against it, including the 119 overlapping permissive policies.
Review every SECURITY DEFINER function: anon-executable (22), authenticated-executable (57), search_path, trigger-only functions still exposed. Also the 4 SECURITY DEFINER views.
Column-level exposure in profiles (tokens, subscription fields) and the prevent_role_self_change coverage.
Storage: both buckets are public. Check whether inspection/apiary images reveal locations or private data, and whether URLs can be guessed.
Live-only objects (queen_assignments, archive_hive_cascade, ensure_reared_queen_record, trace_labels and others) audited from the live DB. Leftover *_backup_20260829 tables noted.
Security and performance advisors snapshot recorded.

1B: Edge functions

Verify suspicion 1 against the deployed version (get_edge_function). Confirmed (SEC-H1); also found a service-role key in a DB trigger (SEC-H5).
Find the source for the 2 deployed functions that are missing from the repo (generate-vegetation-info, send-rearing-group-invitation).
CORS * and caller-supplied names in the invitation and notification emails (phishing relay risk).

1C: API routes (25 handlers)

Per route: auth check, how the service-role queries are scoped to the user, input validation, error-message leaks, rate limiting.
Specific checks: beep/data/wolf-waagen/data device ID not tied to the hive, invoice email HTML injection, auth/verify redirect_to and the Supabase redirect allow-list, update-user-role last-admin race, stripe/checkout code-use race.
Cost and abuse: no rate limits on chat, voice transcription, news search or geocode.

1D: Client, PWA and headers

Service worker caches /api/* GET responses with no per-user key and no purge on logout (shared-device leak).
No Content-Security-Policy or Permissions-Policy on the main app. Draft a CSP that works with Mapbox, Stripe and Supabase.
No middleware: confirm every protected page fails safely without a session (data protection relies on RLS).

1E: AI assistant

Audit the 13 AI tools against the ai tools skill (they run on the service role, so every query's user_id scoping is checked by hand).
Prompt injection: client-supplied assistant turns in the chat history, knowledge-base content and team members' notes. Gaps in the admin URL-fetch SSRF guard (redirects, IPv6, DNS rebinding).

1F: Secrets and supply chain

Secrets scan over the full git history (gitleaks or similar), plus npm audit.
Local exposure in OneDrive: .codex/config.toml holds a Supabase access token (recommend rotating). Also .env - github contributoe.local (whose keys?) and a 22MB production DB export in sql/.
Tracked supabase/.temp/; deprecated or unused dependencies (@supabase/auth-helpers-nextjs, @google/generative-ai); .env.example is git-ignored.
Recheck open items from the February audit: SEC-4/18 (rate limits), SEC-5 (plaintext tokens), SEC-6 (CSRF decision), SEC-7 (admin audit trail), C3 (/api/users/list).

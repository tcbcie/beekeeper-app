WP02 – Protect unfinished observations

Plan: docs/features/mobile-first-implementation-plan.html (WP02 and its refinements). Baseline: docs/features/mobile-first-wp01-baseline.md (S01, S02, S09, S10, S11, S15, S17).

Six small changes in three files, plus one optional field on the stored draft. No database change. No wording changes beyond the one false message (the rest belongs to WP03).

Changes

  1. Say when the phone could not keep a copy (S10, S11).
    • src/lib/inspection-draft.ts: saveInspectionDraft returns 'saved', 'saved-without-photos' or 'failed' instead of nothing. A draft kept without its photos records how many were left out (new optional photosLeftOut on the draft type in src/lib/local-db.ts; old drafts simply lack it, so no Dexie version change).
    • InspectionForm.tsx: when the last write was not complete, one line under the stepper says so. "This phone could not keep a copy of this inspection. Save it before you close the app." or "Your photos are not kept on this phone until you save. Notes and readings are." It clears when a later write succeeds.
    • Resume panel: adds "Photos were not kept." when photosLeftOut is set.
  2. Start again asks first (S09). InspectionForm.tsx startAgain uses the form's existing confirmDialog: "Delete the unfinished inspection? Its notes and readings will be lost" (plus "and N photos" when there are some), with Keep it / Delete it. Keep it leaves the panel as it was.
  3. The Records Home button asks first (S01, S02). records/page.tsx: the button awaits the existing confirmDiscardOpenForm, the same check as Close and the sidebar links. That function already clears the draft on Discard and does nothing when the form is clean.
  4. Leaving never drops the last few seconds of typing (S01 detail, browser Back). InspectionForm.tsx: the 800 ms autosave timer is kept in a ref, and when the form closes with a write still pending, it is written straight away. Saves and Discard are unaffected: a save writes and stops autosave first, and Discard waits on the dialog for longer than 800 ms, so nothing is pending by then.
  5. A save that could not be stored or sent no longer deletes photos or risks a duplicate (S15, S17). records/page.tsx saveNewInspection:
    • That case no longer calls discardQueuedInspection. That call deleted uploaded photos even when the row might have arrived.
    • The unsent attempt is remembered while the form is open. Tapping Save again with nothing changed reuses the same inspection id, task ids and uploaded photos. If the first try did arrive, the server refuses the repeat as a duplicate, and the existing code already counts that as arrived. If anything was changed, it starts afresh, as today.
  6. The false "still here on this phone" message (V02). It is used for new inspections and for edits, and in both cases what is true is that the work is still in the open form. New text: "The inspection could not be sent. It is still in the form, so keep this screen open and tap Save again when you have signal."

Not changed, and why

  • An unreadable stored draft (S12): the app cannot show or recover it, so keeping it would only stop new drafts being kept. It stays as it is; the reason is noted in the docs.
  • Browser and swipe Back stay unguarded by design (the plan treats them separately). Change 4 means the draft is complete when they are used.
  • Edits keep no draft, as today (the plan assesses edit recovery separately). Change 3 protects them from the Home button.
  • "On this phone" on a desktop and the other outbox wording: WP03.

Review

Built as planned in four files, plus a one-line hardening in src/lib/inspection-outbox.ts found by the QA audit.

  • inspection-draft.ts: the save reports its result; a copy kept without photos records how many; a clear counter stops a write queued before a Discard or Start again from bringing the draft back. The close-time write depends on this.
  • InspectionForm.tsx: the autosave timer is kept in a ref and written when the form closes; a status line under the step bar; Start again asks first; the Carry on panel says when photos were not kept.
  • records/page.tsx: Home goes through the same discard check as Close; an unstored, unsent save is remembered and reused if Save is tapped again unchanged, and its photos are no longer deleted; the no-signal message is true for new and edited inspections.
  • QA audit: one High. An attempt that is never stored is retried from memory, and the super change was only marked done in memory after the call. If the call threw, a retry could have added the supers twice. It is now marked done before the call, in memory as on the device. No other Critical or High findings. Low notes: a double tap on Start again could open the question twice; a live line added to the page may not be read out by every screen reader.
  • Checks: type check clean, lint clean on the changed files, 55 existing tests pass (records forms, navigation guard, mobile screen rules). No build run.
  • Docs: inspection-drafts.md, inspection-outbox.md, the WP01 baseline (expected results) and WP02 progress in both plans.

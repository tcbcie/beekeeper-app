Honey Super Fullness — Plan & To-Do

Goal: Let a beekeeper record, during an inspection, how full each honey super is (0–100%). The number of controls is dynamic — driven by the hive's current honey-super count (one super → one control, four supers → four controls). The section is optional and collapsible, consistent with the other inspection sections. The most recent recorded value is then shown graphically as a mini gauge beside each drawn super on the hive card.

Design decisions (confirmed with user)

  • Recording control: one <input type="range"> slider (0–100%) per super, with the current % shown large beside it. Native range = biggest, most reliable touch target on mobile; suits users 50+ with reduced eyesight.
  • Card display: a small circular mini gauge (pie/arc) drawn beside each honey super, showing the last recorded fullness. No fill inside the box.

Data model (follows existing precedent)

The established pattern for optional, variable-length inspection data is a nullable jsonb column typed as a small array — exactly how brood_frames_per_box already works. We mirror it:

  • New column inspections.honey_super_fullness — jsonb, nullable, default NULL. Holds number[], one 0–100 integer per super, index 0 = bottom super.
  • NULL = "not recorded" (section never opened). This cleanly distinguishes not recorded from a genuinely recorded 0%.
  • How many controls to show = the hive's current configuration.honey_supers count. When editing an older inspection whose stored array is longer, show max(stored.length, current count) so no recorded data is hidden.

Review — completed

Status: Implemented, including the 3D yard view (added at user request). Version bumped 1.9.3 → 1.10.0 with a changelog entry.

What changed

  • Database: added nullable jsonb column inspections.honey_super_fullness via Supabase MCP migration (add_honey_super_fullness_to_inspections). No advisor warnings introduced (additive nullable column, no RLS/policy surface).
  • Types (src/types/records.ts, src/types/hive.ts, src/hooks/useApiaryMap.ts): added honey_super_fullness: number[] | null to Inspection/InspectionFormData (+ default null), last_super_fullness to Hive and MapHive.
  • Inspection form (InspectionForm.tsx): new collapsible “Honey Super Fullness” section, one 0–100 slider per super, count driven by the selected hive’s configuration.honey_supers (and never fewer than an edited inspection’s stored values). The array is created lazily — an untouched section stays null (“not recorded”) so it never shows a misleading 0% gauge. Auto-expands in edit mode when data exists; hidden entirely when the hive has no supers.
  • Save (records/page.tsx): values sanitised to whole 0–100 integers (or null) before insert/update; edit-mode form seeding carries the field through.
  • Read-only inspection card (InspectionCard.tsx): compact “Super Fullness: Super 1: 60% · …” line when recorded.
  • Hive card 2D (hives/page.tsx + new SuperFullnessGauge.tsx + HiveListCard.tsx): the latest inspection’s fullness is attached per hive and drawn as a small amber ring gauge beside each super. Supers with no recorded value keep their original centred label.
  • Yard 3D (useApiaryMap.ts + Hive3D.tsx): latest fullness fetched per hive; each super shows a proportional honey-coloured fill rising from its base on the front face — the 3D-appropriate analogue of the ring gauge (avoids per-super HTML overlays that would clutter a busy yard).

Defensive / robustness notes

  • null vs []/0 kept strictly distinct end-to-end: not-recorded never renders as 0%.
  • All fullness reads guard with Array.isArray + Number.isFinite and clamp to 0–100, so malformed/legacy JSON can’t crash a render (consistent with the PostgREST-embed-shape caution in project memory).
  • 3D fetch mirrors the 2D card’s “newest inspection wins” rule and degrades gracefully (logs, doesn’t throw) if the query fails.

Known trade-offs (documented, intentional)

  • Slider count reflects the hive’s super count at the moment of recording; a super added via the same inspection’s Given/Taken adjustment isn’t reflected until the hive count updates on save.
  • The card gauge reflects the last inspection that actually recorded fullness (last known level), not strictly the most recent inspection — because fullness is optional and most inspections leave it unrecorded, so a strict-latest rule would almost never show a gauge.

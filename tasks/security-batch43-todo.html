Batch 43: Settings and Admin

Status: Implemented 25/10/2026, waiting for your test. This is Phase 2 fix batch 30. It covers the open Medium findings in chunk 9a (settings, admin, profile, support): C9a-05, 07, 08, 10, 12 to 17, 25, 26. Three agents checked each finding against the code and the live database (counts only), and I re-checked the key lines. No database change.

A. Your profile: C9a-08, C9a-07, C9a-05

C9a-08, preferences that undo themselves: turning on CRM or Logbook saves it, but the page still remembers the old value. Press Edit Profile, then Cancel, and the toggle flips back off while the database still says on. Saving a new payment link and then making a typo snaps the field back to the old link. Two quick taps whose saves land out of order can also leave the screen out of step with what's stored. Now a save updates the page's remembered profile, and a failed save only rolls back if no newer change has been made since.
C9a-07, subscription and feature checks:
  • Failed checks were remembered: one failed check, for example on a poor signal at start-up, was remembered for 5 minutes. That locked CRM, the Apiary Map and Logbook, and hid the expiry warning. A failure is no longer remembered, so the next check tries again.
  • Results could cross accounts: a check still running when you sign out could save its answer under the next account. Now it can't.
  • Renewing didn't refresh: after renewing, menus and the profile's CRM, Apiary Map and data-export options stayed as "expired" until a reload. Renewing now refreshes them.
C9a-05: the admin "enable/disable account" toggle would show an error after a successful change if the database ever returned nothing. It can't today, but the guard costs one character.

B. Admin tools: C9a-10, C9a-12 to C9a-17

C9a-10, ticket stats: the counts are worked out from the filtered list. With the default "open" filter, Total equals Open and every other count shows 0. Now all tickets load (15 today) and the filter only narrows the list, so the counts are right.
C9a-12 to C9a-14, silent admin failures:
  • News publish/unpublish: does nothing visible on failure.
  • Association list: if it fails to load, you then can't create association codes, with no reason shown.
  • New-owner list: the apiary transfer list can be silently empty.
  • An expired session: stops knowledge base, news and transfer actions without a word.
  • Error messages: about a dozen admin errors show "Unknown error" instead of the real reason, and the "code already exists" message could never appear.
Each now says what went wrong.
C9a-15, lists capped at 100: the knowledge base and news lists load at most 100 items, and search only looks at those. There are 55 and 10 today. The limit goes to 1,000, with a warning if there are ever more.
C9a-16, PDF uploads: the screen says PDFs up to 5 MB, but anything over about 3.3 MB is refused by the hosting before it arrives, with only "Failed to add content". Now the limit is 3 MB everywhere, a larger file is caught before uploading with "PDF too large (max 3 MB): split it or paste the text", and a server refusal gets its own message.
C9a-17, search: the admin searches filter on screen and are fine. The live one is the news search on the About page, where an older, slower answer could replace newer results and stop the spinner early. Now an older search is cancelled.

C. Sizes for 50+ eyes: C9a-25, C9a-26

About 96 changes in 12 files: user management, associations, dropdowns, registration codes, tickets, treatments, the knowledge base, news, conservation areas, your profile, support and subscription history.
  • Fields: 57 fields go from 14px or 12px to 16px and 48px.
  • Checkboxes: 12 checkboxes, some only 12px, go to 20px inside a 48px tap area.
  • Buttons and links: 27 narrow icon buttons and links become 48px wide.
  • Search fields: two had their typing run under the search icon; that's fixed.
Class changes only. Also: "National Organization Memberships" becomes "Organisation".
Decision: the shared checkbox size. The app's shared checkbox is 16px. Changing it to 20px in one place fixes the settings checkboxes and also enlarges the checkboxes on the apiaries, tasks and jar-label screens. Done (you approved).

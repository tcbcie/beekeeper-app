Public phenology feed for tcbc.ie

Status: built, waiting for your tests and deploy  ·  Date: 24 November 2026  ·  Feature doc: docs/features/tcbc-phenology-feed.md (new)

Your request: "read the /opt/projects/tcbcie/docs/hivecraic-phenology-api-brief.md brief and implement".

Your decisions:

  • Observations: community mode only. The feed uses every shared Galway record. Where several people recorded the same event in the same year, it takes the earliest start, that record's GDD and the latest end.
  • Colony events: Brood and Pollen stay in the feed as category colony.
  • Default dates: 02-01,03-01,04-01,05-01.

The previous plans that were in this file are in git history (5caa7f2a, and the hives Select button plan in 0e4b6d20).

1. What I found

  • public_galway_gdd exists in the database and anon can read it. It is built on shared_gdd_records_community, which is internal and has no client grants. It already returns only id, vegetation_type_id, vegetation_name, year, start_date, end_date, gdd_value, city, with no user ids or coordinates.
  • Missing migration files: neither view has a file in supabase/migrations. Both were applied through the MCP at the time, so the database already lists them in its migration history.
  • The narrow read path already exists. Because the feed is community mode, it can read public_galway_gdd with the anon key. No new database function is needed, and gdd_records and get_shared_gdd_records() stay closed to anon.
  • No vegetation type called Brood or Pollen exists yet, so every event is a plant for now.
  • The temperature fetch, including the Open-Meteo URL, the time-limit race that keeps Next's fetch cache working, and the 6 h / 30 day revalidate, lives inside src/app/api/embed/gdd-archive/route.ts. I'll move it into a small shared helper so both routes make the same cached upstream call, one per region and year.

Two differences from the brief to know about

Brief saysWhat the data saysWhat I'll do
Snowdrops 2025 = 2025-01-30, GDD 78.9The shared records hold 2025-01-30 with GDD 77.0 (Galway city) and 77.3 (Mace). 78.9 comes from tcbc.ie's own historic table.Publish what HiveCraic holds. For a tie on the earliest start, take the lower GDD so the result is deterministic. The feed will say 77.0.
Keys like gorse, cherry-plumThe names include Latin in brackets, e.g. "Cherry plum (Prunus cerasifera)", "Clover (Red)", "Clover (White)"Slug the whole name: cherry-plum-prunus-cerasifera, clover-red. Dropping the brackets would merge Red and White clover into one key. TCBC treats the key only as an identifier, so this is safe.

2. How it fits together

 tcbc.ie (server, 6 h cache)
        │  GET /api/embed/phenology?region=galway&years=2025,2026
        ▼
 route.ts ── validate region / years / dates ──► 400 on bad input
        │
        ├─► Supabase (anon key) ── public_galway_gdd ──► events[]       (error → 502)
        │
        └─► fetchEmbedArchive(region, year) for each year and year − 1
                (same cached Open-Meteo call as gdd-archive)              (any failure → 502)
                     │
                     ▼
            calculateGDDFromDaily (src/lib/gdd.ts, unchanged) ──► gdd_sums[]
        │
        ▼
 JSON v1 + Cache-Control: public, s-maxage=21600, stale-while-revalidate=86400   (current year included)
                          public, s-maxage=2592000                                (past years only)

Checked against real data

I ran the builders against the live Open-Meteo archive for Galway, at 53.2707, −9.0568:

 GDD sum      2025     2026    2026 reached in 2025
 02-01        91.7     81.8    2025-01-31
 03-01       243.2    237.2    2025-03-01
 04-01       513.4    489.9    2025-03-31
 05-01       845.5    785.7    2025-04-27
 (2025 reached in 2024: 2024-02-02, 02-28, 04-03, 05-07)
  • The 1 February 2025 total doesn't match the old table. HiveCraic's formula at the Galway centroid gives 91.7. tcbc.ie's historic table shows 85.5, so that figure came from another source or location.
  • The formula matches the stored records. At an apiary around 53.40, −9.10 the same code gives 77.1 for 30 January 2025, against 77.3 in the stored Mace snowdrops record. Stored record GDDs are worked out per apiary.
  • Snowdrops 2025 publishes as 77.0. Two records share the earliest start, and the lower GDD is chosen.
  • Merging works on sample records: the snowdrops records merged into one row, gorse from December sorted first, and a record with no GDD fell back to the accumulated value.

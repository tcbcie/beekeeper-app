2. What I found

None of the existing stores data can drive the dial, so this needs a new column.

Existing columnWhat it really isWhy it can’t be used
honey_storesOld text values (Good, Medium, Low) on 100 of 1,898 inspectionsNo form writes it any more, and the newest value dates from 15/11/2025.
store_framesA count of frames given or taken in that visitIt records a movement, not a level, and defaults to 0.
honey_super_fullness0–100% for each superIt measures supers, which are usually off for winter.
weightGross hive weight, on 86 inspectionsToo sparse, and it includes the hive and bees.

Honey Super Fullness already solved most of this: a 0–100 slider, NULL for “not recorded”, and a card showing the last inspection that actually recorded a value. I’ll follow that pattern. The hive list already loads each hive’s inspection history, so the dial adds no extra requests.

3. Decisions I’ve built into the plan

TopicDecisionWhy
Bands 0–39 red, 40–79 amber, 80–100 green, in steps of 5 Your ranges overlap at 40 and 80, so each boundary takes the better colour. Defined once, in one helper.
Colour plus words The % and a word (Low, Top up, Enough) always sit beside the colour The colours alone are hard to read in sunlight, for colour-blind users and with reduced eyesight.
No reading Grey “Not checked”, never red A grey dial means “go and check”. Red would claim the hive is short of food when nobody knows. It also follows the existing rule in seasonal-lead.ts:95.
New inspection Starts as “Not recorded”. It shows the last reading for reference, and Record stores starts the slider there (or at 50 if there is none) Stores change between visits, so silently copying the last value would make an old guess look like a new reading. Inspections that skip the section leave the dial unchanged.
Which inspection counts The newest one that recorded stores, with its date shown Same as Super Fullness. An inspection that skips the section must not blank the dial.
Dial placement Its own row in the card’s details, not in the status pills at the top The pill cluster already wraps on narrow phones, and the dial needs room for its text.
Archived hives No dial Same as the Queenless pill.

4. Decisions I need from you

QuestionMy recommendationAlternative
A. What does 100% mean? This matters most, because everyone needs to read the gauge the same way. 100% = enough to get through winter, with a hint under the slider: “100% is about 18 kg”. That is the rough guide the app already uses. Green would then start at about 14 kg and amber at about 7 kg. Please confirm those figures suit your hives. 100% = every available frame full. That depends on hive size, so 80% wouldn’t mean the same thing on every hive and “sufficient” would be lost.
B. When does the dial show? Hives are rarely opened from November to February, so October’s reading has to last, but it shouldn’t still be on the card next summer. 1 August to 30 April, using readings taken since 1 August. Hidden from May to July. The form section stays available all year. Always show the last reading and its date. Simpler, but a green dial from last winter would sit on the card all summer.
C. Are the words right? Low, Top up, Enough. Each one says what to do. Low, Medium, Good, which match the old honey_stores values.

5. The change

Database

alter table public.inspections
  add column stores_level smallint
  check (stores_level between 0 and 100);

It is nullable, so existing inspections stay untouched and read as “not recorded”. inspections has table-level grants and no database function lists its columns, so nothing else on the database side needs changing.

Known limit

If one hive has two inspections with stores on the same date, the list picks between them by ID, not by time. Super Fullness behaves the same way and it should be rare, so I’m leaving it as it is.

7. Review

You approved all three recommendations: 100% means enough for winter (about 18 kg), the dial shows from 1 August to 30 April, and the words are Low, Top up and Enough.

What changed

  • Database: inspections.stores_level is live on the production database. It is nullable, so no existing inspection changed. The security advisors flagged nothing related to it.
  • Form: a Stores Level section in step 2, plus the review step and the step description.
  • Hive card: the new dial, fed from the history the list already loads, so it adds no requests.
  • History: the reading shows on the inspection record card and in the hive detail history.
  • Mel: both tools now use the reading.

Additions beyond the plan

  • Mel’s look-back: the feeding tool only looks back 14 days by default, which would have missed October’s reading by December. It now uses each hive’s latest reading since 1 August.
  • Mel’s answer: Low and Top up both count as needing feed. A hive with a reading no longer gets flagged by the older signs. This matters because one of those signs is “one super or fewer”, which is true of most hives in winter.

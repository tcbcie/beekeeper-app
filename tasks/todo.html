Per-cell breeder as mother in the mating-nucs path

Context

Third application of the multi-breeder fix. Mating nucs record their mother/breeder queen in mating_nucs.queen_id, which both creation paths seeded from the batch-level rearing_batches.mother_queen_id. For multi-breeder batches that is NULL, so nucs were created with no mother queen.

Fix (code only — no backfill needed)

Bulk creation — src/hooks/useMatingNucBulk.ts:

  • AvailableSealedGraft + the sealed-cell query now include breeder_queen_id.
  • Each nuc row’s queen_id is the breeder of its specific cell, falling back to the batch mother queen for single-breeder/legacy cells or cell-less nucs.

Single-nuc form — src/components/batches/MatingNucsTab.tsx:

  • Graft type gains breeder_queen_id (the fetch already uses select('*')).
  • Selecting a cell auto-fills the “Grafted from” queen from that cell’s breeder (was only set from the batch mother on batch change).

No backfill required

A check for existing mating nucs from multi-breeder batches whose queen_id differs from their cell’s breeder returned zero rows, so no data correction was needed (unlike the distributed-queen fix).

Review

  • Consistent root-cause fix: per-cell breeder preferred, batch mother as fallback — same pattern as the Queen Tracker and distributed-queen fixes.
  • Backward compatible: single-breeder cells carry breeder_queen_id == mother_queen_id; legacy/cell-less nucs use the batch mother. No behaviour change for them.
  • Ownership safe: mating nucs are created by the batch owner from their own batch, so linking the owner’s breeder queen raises no cross-user concern.

Not build-tested locally (per project workflow). Please create a mating nuc (single + bulk) from a multi-breeder batch and confirm the nuc shows the correct breeder/mother queen.

Profile Page — Layout & UX Reorg

Goal: Regroup the profile page into a clear, purpose-driven structure. No behaviour change, no component extraction — every handler, toggle and state stays exactly as-is; only the order and grouping of the existing blocks change.

Before → After

Current (scattered)
  1. Profile Information
  2. Manage (Scales, Apiary Team, Rearing Team)
  3. Theme Preferences
  4. Subscription (status + history)
  5. Data Export (gated)
  6. Additional Settings (Change Password · Email reminders · Printing · CRM)
  7. Danger Zone
Proposed (grouped by purpose)
  1. Profile Information — who you are
  2. Subscription — status + history, with Data Export folded in beneath (both subscription-related)
  3. Preferences — Appearance (Theme) · Email Notifications (task/event/frequency) · Features (Label printing, CRM)
  4. Tools & Teams — the current "Manage" links
  5. Account — Change Password, then Danger Zone (Delete Account)

Why this is better

  • One home for preferences: Theme + notification toggles + feature toggles (Printing, CRM) all sit together, instead of Theme being orphaned at the top and the toggles buried in a catch-all.
  • Data Export rejoins Subscription: it's subscription-gated, so it belongs with the subscription block, not floating between unrelated panels.
  • No more "Additional Settings" grab-bag: account security (password) moves to a dedicated Account group with the delete action; feature toggles move to Preferences.
  • Destructive actions last: Change Password + Delete Account grouped at the bottom, matching the existing field-journal convention.
  • Audience fit: fewer, clearly-labelled sections reduce hunting — important for the 50+ / reduced-eyesight users. Existing font sizes and touch targets are preserved (this is reorg, not restyle).

Implementation (low-risk, in-place)

  • Reorder the existing top-level section blocks into the 5-group order above (cut/paste of intact JSX blocks — no logic touched).
  • Move the gated Data Export panel to sit immediately under the Subscription block.
  • Group ThemeSwitcher, the Email Notification toggles, and the Printing/CRM toggles under a single Preferences heading (keep each existing sub-card; just relocate Theme up and drop the "Additional Settings" wrapper title).
  • Pull Change Password out of the old "Additional Settings" into an Account group directly above Danger Zone.
  • Rename the "Manage" heading to Tools & Teams and place it after Preferences.
  • Minor consistency: switch the Profile Information wrapper from a raw <div className="bg-surface…"> to <Panel> so all sections share one surface style.
Explicitly out of scope (not selected): extracting the 4 near-duplicate toggle blocks into a shared component, and any font/contrast restyle. Flagged for later if wanted — kept out to keep this change purely structural and safe.

Quality Audit — Hardening Pass

A senior review followed the reorg. The reorg itself added no runtime risk (pure block moves), but it put the five preference handlers side-by-side and exposed pre-existing debt, now fixed:

  • Medium — DRY: five near-identical inline optimistic-update handlers (~120 lines) collapsed into one updatePreference(key, value, onSuccess?) helper; each call-site is now a single line.
  • Medium — fragile revert: handlers reverted to !newValue (only coincidentally correct for booleans). The helper captures and restores the actual previous value, so it's safe for any field type (incl. the frequency string).
  • Medium — guard ordering: handlers wrote optimistically then checked userId, leaving a silent desync if absent. The helper reverts on both the no-user and error paths.
  • Behaviour preserved: the CRM toggle's notifyCrmPrefChanged side-effect is retained via the onSuccess callback; all column names and toasts unchanged.

Plan — Search a Nuc by Number on the Nuc Setup tab

Goal

On Queen Rearing → Nuc Setup, let the user type a nuc number (e.g. A-06) into a search box and have the list instantly narrow to the matching nuc so its record can be pulled up.

What I found

  • The tab is rendered by src/components/batches/MatingNucsTab.tsx. Nucs are a flat, collapsible list (nucs.map, ~line 1492). No search box exists today.
  • The searchable identifier is nuc_number (free-text), with reference_code as a fallback for unnumbered bulk nucs.
  • A nuc’s “record” is the inline expandable card (toggleExpand / expandedNucId) — there is no separate detail page, so “pull up the record” = filter to it and expand it.
  • No DB / RLS / type changes are needed — this is a pure client-side filter over already-loaded nucs.

Proposed change (single file)

  • ☐ Add a nucSearch state (string, default '').
  • ☐ Add a compact search input with a magnifier icon and a clear (×) button, placed just above the nucs list (below the “Nucs by Batch” summary). Mobile-first, full-width on small screens. Honours the 50+ minimum font sizes.
  • ☐ Derive visibleNucs = nucs.filter(...) matching the trimmed, case-insensitive search against nuc_number and reference_code. Render visibleNucs instead of nucs.
  • ☐ Point bulk-select (selectableNucs / Select-all) at the visible list so “Select all” matches what is shown while searching.
  • ☐ When the search yields exactly one match, auto-expand that nuc’s card so the record opens immediately.
  • ☐ Update the empty-state copy to say “No nucs match ‘…’” when a search is active.
  • ☐ Update docs/features with a short note on the new nuc search.
Scope guardrails: one component touched; no schema, hook, type, or routing changes; existing batch filter and Retired toggle keep working (search is applied on top of whatever list is loaded). Search is scoped to the currently loaded active/retired list — clearing the batch filter searches all nucs.
Decision to confirm: Should search look across all active nucs regardless of the current batch filter, or only within the batch you’ve selected? Default plan: search whatever is currently loaded (respects the active batch filter / Retired toggle).

Review

Implemented as a single-file, client-side change in src/components/batches/MatingNucsTab.tsx. No DB, type, hook, or routing changes.

  • ☑ Added nucSearch state and imported useMemo + the Search icon.
  • ☑ Added a full-width search input (magnifier + clear button) above the nuc list, with text-base sizing for the 50+ audience and aria-labels.
  • ☑ Derived visibleNucs via useMemo (case-insensitive match on nuc_number / reference_code); the list and empty state now render from it.
  • ☑ Per your choice, typing auto-clears the active batch filter so search spans all active nucs.
  • ☑ Bulk-select (selectableNucs / Select-all) now derives from the visible list, so it matches what is shown while searching.
  • ☑ A single match auto-expands that nuc’s record card (effect guarded so it only fires while searching, never conflicting with the existing deep-link highlight).
  • ☑ Search-aware empty state: “No nucs match ‘…’”.
  • ☑ Documented in docs/features/mating-nucs.md (new “Nuc Search” section).
  • ☑ Follow-up (approved): search now also reaches retired nucs without the “Show Retired” toggle. While a search is active, fetchNucs drops the retired filter so both active and retired load. Gated on an isSearching boolean added to the useCallback deps, so it refetches only when search starts/ends — not on every keystroke.

Please test: on Queen Rearing → Nuc Setup, type a nuc number (e.g. A-06) — the list should narrow, the batch filter should clear, and a single match should open its card. Clearing the box restores the full list.

Honey Provenance — explain Bulk Honey vs Batches vs Jar Labels

Problem: the three sub-tabs give a novice no clue what each one is, or in what order to use them. Nothing on the page names the flow.

The flow to be taught

Harvest (Records)  →  Bulk Honey (bucket)  →  Batch (bottling run, lot code)  →  Jar Label (printed design + QR)
TabWhat it isWhen you create one
Bulk HoneyThe bucket, tank or drum the extracted honey sits in. Links back to the harvests that filled it, which is where the apiary origin comes from.Extraction day — one per bucket
BatchesOne bottling run: honey drawn out of one or more buckets and put into jars. Carries the EU lot code (L-2026-08-001) and best-before date.Bottling day
Jar LabelsThe printed label design, one per jar size. Its QR code never changes, so labels can be printed in bulk once and reused — on bottling day you just re-point the label at the new batch.Once per design, then reused forever

QA audit (qa-engineer)

No Critical or High findings. The one genuine risk was investigated and cleared:

  • 🟢 SSR hydration mismatch — not present. usePersistentState returns its default on the server and the stored value on the client, which would mismatch if the stored value were false. It cannot happen here: tools/page.tsx:54 gates on userId, resolved in a client effect, so TraceabilityTool never appears in server-rendered HTML.
  • 🟡 Weak icon typing — icon: typeof Package pinned the field to one icon's type instead of the shared contract. Fixed: LucideIcon.
  • 🟡 No touch feedback — the header defined only hover:, and a phone has no hover, so a tap looked inert. Fixed: added active:bg-amber-500/20.
  • 🟡 Chain unreadable to screen readers — the arrows are aria-hidden, so the four names ran together as one phrase. Fixed: a visually-hidden "then" between each.

Mating Nucs — Virgin Queen nucs missing from batch filter

Problem

Clicking “View Nucs” on a bulk run shows only nucs from that exact bulk creation run (filtered by creation_batch_id). Virgin Queen nucs created individually via the “New Nuc” form have creation_batch_id = NULL, so they are excluded even though they belong to the same rearing batch.

Fix (confirmed with user)

Make the “View Nucs” filter operate at the rearing-batch level (batch_id) instead of the bulk-run level (creation_batch_id), so all nucs of the batch appear regardless of how they were created.

Tasks

  • Diagnose root cause via direct DB query
  • Confirm desired filter scope with user
  • Rename activeBulkBatchId → activeBatchId for clarity
  • Filter fetchNucs by batch_id instead of creation_batch_id
  • “View Nucs” sets the filter to run.source_rearing_batch_id
  • After bulk create, set filter to the source rearing batch id
  • Update empty-state copy to reference “batch”
  • Update docs in docs/features

Review

All changes confined to src/components/batches/MatingNucsTab.tsx plus doc updates.

  • Renamed state activeBulkBatchId → activeBatchId (now holds a rearing-batch id, not a bulk-run id).
  • fetchNucs now filters .eq('batch_id', activeBatchId) instead of creation_batch_id.
  • “View Nucs” sets the filter to run.source_rearing_batch_id; post-bulk-create sets it to bulkFormData.source_batch_id.
  • Empty-state copy updated to “selected batch”.

Result: clicking “View Nucs” on TQRQB_RZ02 now returns all 9 nucs (4 cell-introduced + 5 virgin), not just the 4 from the bulk run.

Quality audit (no test code added)

  • Null safety: if a bulk run has no source_rearing_batch_id, the filter clears (shows all) rather than erroring — acceptable, and runs always carry a source batch in practice.
  • Closure correctness: bulkFormData.source_batch_id is captured before resetBulkForm() runs, so the filter is set to the correct batch.
  • No regressions: the graft-status sync guard (!activeBatchId) and dependency arrays remain consistent after the rename.

Profile page — denser, mobile-first settings

Target: src/app/dashboard/profile/page.tsx (1,535 lines)

The problem, measured

The page is a single narrow column of ten identical full-width accordion panels. Every one of them then wraps its content in another bordered card, and inside that, each individual setting gets a third bordered card. Three nested frames to show one on/off switch.

The same triple-framing hits Profile Information hardest: eight short values (first name, last name, mobile, address, breeder code, NI/UK, associations) each get their own bordered box. On a phone that is roughly 720px of scrolling to read a name and a phone number.

Mobile order matters. A two-column desktop grid built from two stacked <div>s means column A's items all precede column B's in the DOM. The order above is chosen so the phone reading order still makes sense: identity → details → money → the things you toggle → the things you rarely touch.

  • The edit form, all modals (change password, delete account, renew subscription), and the export buttons keep their current markup.
  • Switch styling, colours, and the persisted open/closed state per section stay identical.
  • No new dependencies.

Accessibility / audience guards

  • Users are 50+ with reduced eyesight — descriptions stay at text-sm, never dropping to text-xs where they currently sit at text-sm. Density comes from removing frames and duplicated prose, not from shrinking type.
  • Every toggle row is ≥48px tall and the entire row (not just the 44px switch) toggles it — a bigger target than today.
  • Existing htmlFor/id pairings preserved; aria-expanded/aria-controls on sections untouched.
  • British English throughout.

What changed on screen

  • Identity header — always visible: initials avatar, name, email, and badges for subscription state, breeder code and national memberships. Replaces a bare "Profile" <h1> that repeated the navigation.
  • Three nested borders became one. Sections no longer wrap their content in a second card, and individual settings no longer get a third. The section Panel is the only frame.
  • Duplicated prose removed. Every toggle previously carried a title and a description, then repeated both on the switch row. Now one label, one description.
  • Ten sections became eight — Danger Zone folded into Account as a red-styled row; the confirmation modal still does the real guarding.
  • Two columns from lg:. Column A: Your details, Subscription, Selling your honey, My data export. Column B: Features, Notifications, Appearance, Tools & Teams, Account. Phones and tablets keep one column, and the DOM order is the phone reading order.
  • Tools & Teams switched from 3-across to a single-column list — three cards in a half-width desktop column were 160px wide.
  • Data export lost four bullets that restated the sentence above them.

One deviation from the plan

The plan sketched an Edit button in the identity header. It was not built. CollapsibleSection owns its open/closed state internally (persisted under profile:section:profile), so a header button could set editingProfile while "Your details" was still collapsed — a button that appears to do nothing. Opening the section from outside would mean lifting that state out of the component, which is a bigger change than this redesign warrants. The Edit button stays inside the section, now below the details list rather than above it.

QA audit — second pass

A deeper re-read of the changed code found five further issues, two of them regressions introduced by the redesign itself. All fixed.

SeverityFindingFix
🟠 HighRegression. The new header badge read subscriptionStatus?.is_active, but that state starts null and is filled by a fetch. Every active subscriber was badged "No subscription" on each page load until the request returned — a false claim on the most prominent new element.Render the badge only once subscriptionStatus is non-null. No badge beats a wrong badge.
🟠 HighHeading semantics. CollapsibleSection renders its title as a <span> inside a <button>. With the page's only real heading now the <h1>, a screen-reader user navigating by heading could not reach a single section.Wrapped the disclosure button in an <h2> — the standard accordion pattern. Tailwind's preflight zeroes the heading's margin and font-size, so nothing moves visually.
🟡 MediumRegression. truncate on the header <h1> and email clipped the user's own name and hid the domain half of their address — at 320px there is roughly 230px left after the avatar.break-words on the name, break-all on the email. Both wrap instead of vanishing.
🟡 MediumDetailRow right-aligned its value against the label. Short values were fine, but a wrapped producer address became ragged down its left edge — the hard direction to read, and worse for the audience.Two left-aligned grid columns (sm:grid-cols-[minmax(0,10rem)_1fr]) instead of justify-between + text-right.
⚪ LowThe associations fetch catches and logs its errors, leaving associations empty. "Local association" then reported "Unknown" — a positive claim about data we simply had not loaded.Only claim "Unknown" once the list is non-empty; otherwise "Not available".

Checked and found sound

  • Stale draft in the header. The header reads profileFormData, so an abandoned edit could have stuck. handleCancelProfileEdit (page.tsx:264) fully resets the form from userProfile — no leak.
  • Switch knob positioning. Verified the ::after now resolves against the track, and peer-checked:after:translate-x-full lands it at 22px in a 44px track with a 2px gutter.
  • Panel padding override. cn() in this repo is a plain join(' '), not tailwind-merge — conflicting utilities are decided by stylesheet order, not string order. The header passes padding="none" so no p-* conflict is emitted at all.
  • Toggle id collisions. All seven ids are unique, and CollapsibleSection unmounts closed content anyway.
  • Blast radius. WildColonyInspectionForm declares its own local CollapsibleSection (line 80) and does not import the shared one. Both shared-component changes are scoped to this page.

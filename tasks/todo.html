Plan — Weather-aware spring/summer trade-off (Option B)

Status: Awaiting your sign-off before any code is written. Full design lives in docs/features/planner-weather-aware-spring-floor.md. No database changes.

Problem

The planner currently refuses to break before the spring crop is fully off (T ≥ spring-crop end), so it always protects the spring crop at full forager strength and only optimises the summer flow. You want the opposite to be possible: accept the spring crop tailing off on a declining forager force in exchange for a stronger force for the summer crop — and the spring crop's real end is weather-gated: if the 10-day forecast has no foraging weather, the remaining bloom yields nothing and breaking early costs nothing.

Approach (confirmed: Option B, weather-aware)

  1. Weather-effective spring end — fetch the apiary's 10-day Open-Meteo forecast, score each day with the existing calculateForagingHours(); a day is a foraging day if it has ≥ 1 flyable hour. effectiveSpringEnd = min(bloom-end, last foraging day).
  2. Acceptable-decline floor — a springFloor slider (50–100%, default 80%). Relaxed earliest = earliest break T that keeps spring coverage ≥ floor over [springStart, effectiveSpringEnd].
  3. Recommendation — same objective (maximise summer coverage), now searched within the relaxed, weather-aware range.
  4. UI — floor slider, a forecast note, and a dual Spring X% · Summer Y% coverage readout so the trade-off is visible.

Review

Implemented the weather-aware spring/summer trade-off as planned, touching only the four files above plus the type definition. Summary of changes:

  • Model — planFromResolved gained two optional, backward-compatible parameters (effectiveSpringEnd = null, springFloor = 1). With the defaults its output is byte-for-byte the old "break only after the spring crop is off" behaviour, so nothing that called it before changes. When a floor below 100% is supplied it scans forward from hardEarliest − 30 days and relaxes earliest to the soonest date whose average spring coverage still clears the floor (spring coverage is monotonic in the break date, so the first hit is the earliest valid one). An empty/weather-ended spring window satisfies the floor trivially. Added springCoverageScore to the plan and effectiveSpringEnd to the bounds.
  • Hook — added a guarded 10-day Open-Meteo forecast fetch (aborts with the existing controller, returns null on any failure, clears when the apiary has no coordinates). Each day is scored with the app's authoritative calculateForagingHours. A memo derives the weather-effective spring end with three cases (no foraging weather → finished now; foraging stops early → trim; foraging persists → assume normal past the horizon). New persisted springFloor state (default 0.8).
  • UI — a "Protect spring strength ≥ X%" slider, a forecast note, a dual Spring X% · Summer Y% readout, and a reframed slider warning. Slider range 50–100% with 5% steps and a large hit target for the 50+ audience.

Defensive notes: the forecast fetch and JSON access are fully null-guarded and coerced with Number(); springFloor is clamped to [0,1] in the model; the relaxed-earliest scan is bounded by SLIDER_BACK_DAYS; and all new branches degrade to the prior behaviour when the forecast is unavailable.

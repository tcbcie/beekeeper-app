3D hive — super fullness readability fix

Problem

In src/components/apiaries/Hive3D.tsx each honey super renders its own floating % badge anchored at that super's vertical centre (lines 160–187). Supers are only 0.16 units tall, so the badges pile on top of one another and become unreadable at two supers, worse at three (see reported screenshot). The honey-fill band already conveys fullness visually; the stacked numbers are the noise.

Chosen direction (confirmed)

One side gauge column. Keep the honey-fill bands on the boxes. Replace the N overlapping per-super badges with a single compact vertical gauge rendered beside the stack — one labelled segment per super, ordered top→bottom. One DOM overlay, laid out with flexbox, so segments can never collide regardless of super count.

  ┌────┐   ⎷ 100%   (top super)

  ├────┤   ⎷  70%   (lower super)
  │//  │   ⎻
  └────┘
  fill band on box  +  one gauge column beside it

Review

Single file of application code changed: src/components/apiaries/Hive3D.tsx (plus a feature-doc update in docs/features/apiary-3d-view.md).

  • Root cause removed. The old code rendered one <Html> % badge per super, each anchored at that super's centre. Because supers are only 0.16 units tall, the badges overlapped — unreadable at two supers, worse at three.
  • New readout. One camera-facing gauge column now sits beside the stack. It is a single flexbox <Html> with one row per super (top super first): a small vertical fill bar + a bold %. Because it is one DOM element with stacked flex rows, the rows can never collide, regardless of super count.
  • Always on the camera side. The gauge is anchored on the stack's vertical axis (position={[0, gaugeCentreY, 0]}) so the hive's stored rotation can't swing it out of view, then shifted screen-right in CSS (translateX(calc(50% + 44px))). Since the overlay billboards toward the viewer, it stays on the camera-facing side however the hive or camera is turned; the px offset scales with the hive via distanceFactor, so it clears the box at every zoom.
  • Honey-fill bands kept. The four-face fill band per super is unchanged — it remains the glanceable indicator. Fill still suppressed at 0% / no recorded fullness.
  • Low-vision. text-sm bold amber-900 on white with an amber ring; tabular-nums so numbers don't jitter.
  • Empty state. A hive with no measured supers renders no gauge column (guarded by supersTopFirst.length > 0).
  • Scope. No data-layer, schema, 2D-card, or SuperFullnessGauge changes. Smallest viable diff.

Please test the build (I did not build locally): open a yard's 3D view with hives that have 2–3 honey supers of differing fullness and confirm the gauge column beside each stack is clearly readable and no longer overlaps.

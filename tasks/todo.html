Optional recipient hive when distributing to an app user

Request

When distributing a queen cell, virgin queen, or mated queen to an app user (or group member, who is also an app user), allow choosing an optional recipient hive in addition to the apiary. Optional because the hive may not exist yet.

Key finding — most of this already exists

In DistributeGraftModal.tsx the hive picker, its state (selectedHiveId, hives), the fetch effect, the get_recipient_hives RPC, and saving recipient_hive_id are already implemented — but the dropdown is gated to distributionType === 'mated_queen' only (line ~523).

The data layer (createDistribution / createBulkDistributions in useGraftDistributions.ts) already inserts recipient_hive_id for every distribution type. The hive-fetch effect already runs for all types.

Plan (minimal, UI-only)

  • In DistributeGraftModal.tsx, change the hive-picker render condition from distributionType === 'mated_queen' && selectedApiaryId to simply selectedApiaryId (app user, non-external) — so it shows for cells, virgin queens, and mated queens once an apiary is chosen.
  • Keep it optional: the “Select hive (optional)” placeholder and the empty-list case (recipient has no hives yet) already handle the “hive does not exist yet” situation. Add a small hint when the chosen apiary has no hives.
  • No backend, schema, or RPC change. No bulk-path change (already passes recipient_hive_id).

Out of scope / notes

  • External (“Other Beekeeper”) recipients — unchanged; they have no app apiaries/hives, only a free-text location.
  • Selecting a hive only records the intended destination on the distribution (as today for mated queens). It does not auto-assign the queen into the recipient’s hive; the recipient’s own queen record is still created as before.
  • Decision to confirm: should the recipient-hive picker also appear in the bulk distribution flow (same modal, many grafts to one recipient)? It would apply the one chosen hive to all grafts — usually not desired for cells. Default proposal: show it for single distributions, hide for bulk.

Review

  • One-line gate change in DistributeGraftModal.tsx: the recipient-hive picker now renders for all distribution types when !isExternal && selectedUser && !isBulk && selectedApiaryId (was distributionType === 'mated_queen' && selectedApiaryId).
  • Single only (your choice): added !isBulk so the picker is hidden in the bulk flow.
  • Stays optional: “Select hive (optional)” default kept; added a hint when the apiary has no hives yet (“the hive will not exist yet”).
  • No backend change: recipient_hive_id was already inserted for every type; the fetch effect and get_recipient_hives RPC already ran for all types. Doc updated (docs/features/batch-distributions.md).

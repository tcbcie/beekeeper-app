Mother queen shows “-” in Queen Tracker for multi-breeder batches

Problem

In the Queen Tracker cell detail card, Mother queen (and Mother age) display - / N/A even though the data exists. Observed on Cell #6 of batch TQRQB_RZ03.

Root cause (verified against the live database)

TQRQB_RZ03 is a multi-breeder batch:

  • rearing_batches.mother_queen_id is NULL.
  • It has 2 breeder queens; each cell carries its own batch_grafts.breeder_queen_id (32 cells populated).
  • Cell #6 → breeder queen UGMul1.8 (AMM, Blue, born 2025-05-25).

useQueenTracker resolves the mother queen only from rearing_batches.queens!mother_queen_id, so multi-breeder batches come back null and the card renders -.

Fix — single file: src/hooks/useQueenTracker.ts

  • Add a per-cell breeder-queen join to the existing batch_grafts(...) select: queens!batch_grafts_breeder_queen_id_fkey(queen_number, subspecies, marking_color, birth_date).
  • In the row mapping, prefer the per-cell breeder queen and fall back to the batch’s mother_queen_id queen when the cell has none.
  • Extend the local TypeScript types for the batch_grafts join (no any).

No display-layer changes (getMotherQueenLabel and the age logic already read the mother_queen_* fields). No schema change, no migration.

Why this is safe / minimal

  • Backward compatible: single-breeder batches set breeder_queen_id = mother_queen_id per cell, and legacy cells are NULL → the fallback yields the batch mother queen, identical to today.
  • One query select + one mapping branch changed; everything else untouched.

Review

Implemented in src/hooks/useQueenTracker.ts with three small, anchored edits:

  • Query: the existing batch_grafts(...) embed now also pulls the per-cell breeder queen via queens!batch_grafts_breeder_queen_id_fkey(queen_number, subspecies, marking_color, birth_date). Verified there is exactly one FK from batch_grafts to queens, so the embed is unambiguous.
  • Types: the graft destructuring type gained a typed queens join — no any introduced.
  • Mapping: motherQueen = cellBreederQueen ?? batchMotherQueen. The per-cell breeder wins; the batch-level mother_queen_id queen is the fallback. All four mother_queen_* fields flow from this single resolved source, so the display layer (label, age, marking) needed no change.

Safety: null-safe throughout (graft?.queens ?? null → firstJoinedRecord → nullable). Single-breeder batches (cell breeder == mother) and legacy cells (breeder NULL → fallback) render exactly as before. No schema change, no migration, one file touched.

Note: this fix covers the Queen Tracker card only. Other surfaces that show a batch’s mother queen via mother_queen_id (e.g. queen detail/lineage views) were out of scope for this report and unchanged.

Not build-tested locally (per project workflow). Please open the Queen Tracker and confirm Cell #6 of TQRQB_RZ03 now shows Mother queen: UGMul1.8 / Apis mellifera mellifera (AMM) with a real Mother age.

Plan — Planner apiary default + crop data-availability coding

Stop the planner silently using a generic estimate. Default to the user's main data site, and make the crop picker show which crops have real observations. Guidance only — no database changes, resolver logic unchanged (still apiary-scoped).

Root cause: the planner defaulted to the alphabetically-first apiary (often sparse), so a chosen crop with no observation there fell through to the Tier-3 generic estimate — showing misleading "typical GDD" dates with no signal that real data wasn't used.

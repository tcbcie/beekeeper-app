Reports — new "Queen Failures" report

Goal

A standalone Queen Failures tab on /dashboard/reports, mirroring the Archived Hives report: a breakdown by failure reason plus a table of failed queens, with CSV export and print/PDF. Scoped to the current user's own distributed queens.

Layout

Queen Failures Time period: [All] [3M] [6M] [1 Year] [Custom] (no apiary/hive filter) [ Total failed 12 ] [ Drone layer 4 ] [ Died 3 ] [ Superseded 2 ] [ Lost 2 ] [ No reason 1 ] Date Queen Batch Reason Comment 12/07/2026 Queen 38 Spring A Drone layer supersedure cells seen 05/07/2026 Batch B · Cell 4 Summer B Died — … [Export CSV] [Print / PDF]

Data

No schema change. Source is graft_distributions where user_id = current and queen_failed = true, joined to batch_grafts (cell/queen number) and rearing_batches (batch name), with the recipient from profiles/external fields.
  • Date used: queen_failed_date, falling back to distribution_date when the failure date is null (older/backfilled rows). Period filtering is applied on this effective date.
  • Queen label: same rule as the tracker — Queen {tag} when tagged, else {batch} · Cell {N}.
  • Reason breakdown: counts every reason present (null → "No reason recorded"), sorted by count descending. (Archived Hives caps at top 4; failures show all present reasons.)

Out of scope

No group-owner cross-member view (this is the user's own failures only, consistent with the other main-page reports). No new column on graft_distributions.

Suppliers and invoice numbers on expenses

Status: built; database change is live; waiting for your tests  ·  Date: 15 November 2026  ·  Feature doc: docs/features/profit-loss-suppliers.md

Your request: in Tools → Profit & Loss, let an expense pick a supplier, create a new supplier on the spot, edit an existing one, and record the date and the invoice number.

How it was explored: an agent covered the Profit & Loss code and docs; I checked the live database through the Supabase MCP. The Mel voice input plan that was in this file is in git history (aac8caf4).

1. What exists today

  • The form (FinancialRecordForm.tsx, shown inline on the Profit & Loss tool) has: Type (income/expense), Date (already there, required), Amount, Category, Description, Notes.
  • The table financial_records has 117 records (33 expenses) from 4 users. It has RLS by user_id and no supplier or invoice columns.
  • There is no supplier table. The CRM's customers are the closest pattern, but they are a separate opt-in module, so they are not reused.
  • Saves go straight to Supabase in ProfitLoss/index.tsx, with explicit column lists for insert and update.

2. The design

User and moment: a beekeeper at home or in the shed with a receipt or invoice in hand, entering what they bought. One job: record who was paid and the invoice reference without leaving the expense.

  • Supplier and Invoice number appear only for expenses, under Category. Both are optional.
  • The supplier list's first option is "No supplier". Below it are two 48px outline buttons, New supplier and Edit supplier; Edit only shows when a supplier is selected.
  • The sheet uses the existing ModalShell: a bottom sheet on a phone, a centred dialog on desktop. Saving a new supplier selects it in the expense. The toast reads "Supplier saved".
  • The record row gains one line, "Thornes · Invoice INV-20431". The CSV export gains "Supplier" and "Invoice number".
  • Inputs follow the form's existing styling (16px text, 48px tall).

Review against the design rules: I considered a typeahead "search or add" box, but the app has no such primitive and a native select is easier with gloves and large text. I put New and Edit as buttons, not as a "+ Add new…" option inside the select; that pattern is hidden and awkward with screen readers. There is no separate suppliers screen: everything happens where the expense is entered.

3. Database (additive only)

  • New table suppliers (id, user_id, name, phone, email, notes, created_at, updated_at), with RLS auth.uid() = user_id for all four actions, the same as financial_records.
  • financial_records gains supplier_id (nullable, on delete set null, indexed) and invoice_number (nullable text).
  • No existing data changes, so there is nothing to back up beyond Supabase's daily backup. Applied through the MCP, with the SQL saved as supabase/migrations/20261115180000_add_suppliers_to_profit_loss.sql.

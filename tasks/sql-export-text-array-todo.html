SQL export – make text[] values restore

Shared helper: src/lib/database-export.ts. Callers: src/components/settings/ProfileExport.tsx (personal SQL export) and src/app/api/admin/export-all-data/route.ts (complete database export). Both write data rows through buildInsertSql(schema, table, row).

The problem

sqlValue writes every object or array as a quoted JSON string. For an inspection with photos that gives:

INSERT INTO "public"."inspections" (..., "image_urls", ...) VALUES (..., '["https://a.jpg","https://b.jpg"]', ...);

That loads into a jsonb column, but Postgres rejects it for a text[] column (malformed array literal), so a restore fails on the first inspection that has photos.

What the live database says (checked via the Supabase MCP)

  • Array columns in public: only inspections.image_urls (text[]).
  • jsonb columns that can hold arrays or objects: profiles.tool_order, hives.configuration, hive_configuration_history.configuration, inspections.brood_frames_per_box, inspections.honey_super_fullness, knowledge_base.metadata. These must stay as JSON text, which already works.
  • storage.buckets.allowed_mime_types is also text[], but the admin route already turns it into a '{…}' string before calling the helper, so it is not affected and is left alone. auth.users and auth.identities have no array columns.

Approach (smallest correct change)

sqlValue on its own cannot tell text[] from jsonb: both arrive as a JS array. buildInsertSql does know the table and column, so the fix lives there:

// Postgres text[] columns. A JSON string will not load into text[], so these are
// written as ARRAY[...]::text[]. jsonb columns holding arrays (e.g. profiles.tool_order)
// stay as JSON text. A new text[] column in an exported table must be added here.
const TEXT_ARRAY_COLUMNS: Record<string, readonly string[]> = {
  inspections: ['image_urls'],
}

// inside buildInsertSql, per column:
const value = row[column]
if (Array.isArray(value) && TEXT_ARRAY_COLUMNS[table]?.includes(column)) {
  return `ARRAY[${value.map(sqlValue).join(', ')}]::text[]`
}
return sqlValue(value)
  • Each element reuses sqlValue, so quotes in URLs are escaped exactly as today and a null element becomes NULL.
  • An empty array becomes ARRAY[]::text[], which is valid (the cast gives it a type).
  • null stays NULL; every other column and every jsonb value is written exactly as before.
  • Result for the example above: ARRAY['https://a.jpg', 'https://b.jpg']::text[].
  • Why a list rather than reading column types at export time: there is one such column, the personal export has no access to column metadata, and a two-line constant is simpler than a new query. The rule is written next to it and in the doc.

Batch 33: Queen Rearing Records

Status: Implemented 23/10/2026, waiting for your test. This is Phase 2 fix batch 20. It covers the open Medium findings where queen rearing loses or misrecords data, which feeds into NIHBS returns and recipients' queen records. Two agents checked each finding against the code and the live database. The next two batches are CRM and traceability (batch 34), then records and hives (batch 35).

A. Deleting a distributed graft silently deletes the distribution: C5b-09

In the live database, deleting a graft also deletes its distribution: the Queen Tracker row, its NIHBS counts, and the link to the recipient's queen. The lock on a distributed row in the grafts table is screen-only, and one tap takes it off with no warning. After that, the row can be deleted or have its status changed. "Sold" can also be picked by hand on any graft, which drops a mated queen out of the NIHBS return.

Database: refuse to delete a graft that has a distribution, instead of deleting both. Deleting a whole batch still works, because it removes the batch's distributions in the same step.
Screen:
  • Distributed grafts never show Delete or the status picker, even when unlocked.
  • "Sold" is removed from the hand-picked statuses; it's only set by distributing.
  • The bulk status and delete actions skip distributed grafts and say so.
  • A wrong code comment about this rule is corrected.

B. Editing or deleting a mating nuc wipes the old queen's record: C5a-08, C5a-09

When you re-queen a nuc by editing it to a new cell, the old graft is reset to "sealed cell", and its queen number and marking are erased. This happens even if it's mated, failed or sold. Deleting a nuc does the same to an emerged queen. Delete also resets the graft before deleting the nuc, so a failed delete in the field still wipes it. Several of these writes ignore errors and show "success" anyway.

Only a graft still marked "in nuc" is moved back, to "emerged" if it has a marking, otherwise "sealed". Its number and marking are kept.
Delete removes the nuc first, then moves the graft back.
Every write checks for errors, and a partial failure is reported rather than shown as success.

C. A mixed bulk distribution records every graft as a mated queen: C5b-07

If you select sealed cells together with a mated queen and press Distribute, every graft is recorded as a mated queen. This over-counts NIHBS and gives the recipient "active" queens that are really cells.

The Distribute window refuses a selection whose grafts are at different stages and asks you to distribute them in groups. A selection all at one stage works as now.

D. Mated date and Mated tick: C5b-08, C5a-11

C5b-08, database: when you correct a distribution's mated date, the recipient's queen gets the corrected date too. It's only changed where the queen still has the old date, so a date the recipient set themselves is left alone.
C5a-11: clearing "Mated", from the tracker icon or the Mated window, now asks first, as clearing a failure already does. It also keeps the mating location instead of erasing it.

E. Smaller fixes: C8a-14, C5b-06, C6-06, C5b-14

C8a-14, NIHBS return: if loading your saved overrides fails, the report now shows an error. Before, it showed the automatic figures, and pressing Save would overwrite your overrides for good.
C5b-06, bulk distribution: the recipient queens get the mating location and date typed into the window, as single distributions already do.
C6-06, redistributing a queen: your copy is only marked "distributed" once the recipient's queen has actually been created. Errors are shown, not just written to the console.
C5b-14, creating a batch: if saving the breeder queens fails, the half-made batch is removed. Before, a retry failed with a false "name already used" error.
Database changes: one migration, applied through MCP and saved in supabase/migrations/. It changes how a graft's distribution reacts to a delete, and adds one trigger that copies a corrected mated date to the recipient's queen. The trigger function gets no client access, and I'll run the security advisors afterwards. Everything else is screen code.

You:
  1. In a batch's grafts table, a distributed graft has no Delete or status picker, even when unlocked, and "Sold" isn't offered.
  2. Edit a mating nuc to a new cell: the old graft keeps its number and status.
  3. Select a sealed cell and a mated queen together and press Distribute: you're asked to split them.
  4. In the Queen Tracker, change a mated date: the recipient's queen shows the new date. Tapping the Mated tick asks before clearing.

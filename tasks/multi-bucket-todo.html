Multi-Bucket Creation + Moisture Content

Problem

When creating a new Bulk Honey entry, selected harvests may total more honey than fits in a single bucket. The user needs to specify how many buckets the honey will be split across, and the system should create multiple containers with sequenced codes (e.g., BH-01-1, BH-01-2, BH-01-3). Each container also needs a moisture content (%) field to record the honey's water percentage.

Tasks

Review

Database

Added moisture_content numeric NULL to bulk_containers via Supabase migration.

Types (src/types/traceability.ts)

  • BulkContainer — added moisture_content: number | null
  • ContainerFormData — added moisture_content: string and bucket_count: string

TraceabilityTool.tsx

  • Submit handler — when creating with bucket_count > 1, loops and inserts N containers with sequenced codes (base-1, base-2, etc.). Each shares the same harvests, date, type, notes, moisture. Weight left blank for multi-bucket (user fills later). Single bucket behaves exactly as before.
  • Form UI — added Moisture Content (%) input. Added Number of Buckets input (create mode only) with preview text showing the sequenced codes.
  • Card display — shows moisture percentage when present.

Documentation (docs/features/honey-traceability.md)

Added moisture content field and multi-bucket creation section.

Design decisions:
  • Weight is blank on multi-bucket to avoid guessing splits — user fills per bucket after creation.
  • Moisture content is shared across all created buckets (same extraction = same refractometer reading).
  • Bucket count only appears in create mode — editing always targets a single container.
  • When bucket count is 1, no suffix is appended — completely backwards compatible.

WP04 – Make fields, choices and ratings understandable

Plan: docs/features/mobile-first-implementation-plan.html (WP04, refinements, owner decision 3). Findings: F03, F08, I03, I04, V01, V05–V08, DB01. No database change and no change to stored values.

Changes

  1. Secondary forms: labels and choices (F03, V01).
    • PurchaseItemForm.tsx (9 fields) and FinancialRecordForm.tsx (6 fields): every label is linked to its field (htmlFor/id, ids from useId), so tapping a label focuses the field and screen readers name it.
    • Priority (Low/Medium/High/Urgent) and Type (Income/Expense) become native radio groups in a fieldset with a legend, using the existing RadioChoiceGroup/RadioChoiceOption. Selection shows in green, as elsewhere, and is announced. This also fixes "Low" looking the same selected or not.
    • Priority leaves its half-width column, so it has room: Category takes the full width, with Priority below it. The other two-column rows stay for WP06.
  2. Dialog focus (F08), src/hooks/useDialogA11y.ts: the focus list skips controls that are not visible or are inert (checkVisibility where the browser has it), and Shift+Tab from the dialog panel itself now wraps to the last control instead of leaving the dialog (S29).
  3. Rating meanings (I03, V07, V08). renderStarRating in InspectionForm.tsx gets an optional scale. Below the stars, a line reads for example "1 = Very nervous · 5 = Very calm". The same words are added to the first and last star's screen-reader name. RatingButtons.tsx is unused and is left alone.
    • Already established (database comments): Calmness, Swarming tendency, and the six disease ratings (1 = Minimal · 5 = Severe).
    • Needs your answer: the others. See decision D1.
  4. Step ticks (I04): see decision D2. Either way, the misleading isComplete is renamed isVisited.
  5. Queen averages skip unrated zeroes (V05), src/hooks/useQueenDetail.ts: count a rating only when it is above 0, as hive averages and selection scoring already do. The "averaged across N inspections" count then includes only inspections with at least one real rating. This changes the queen page and the queen comparison numbers for queens with unrated inspections. They become correct.
  6. Super fullness (V06, owner decision 3), InspectionForm.tsx and records/page.tsx:
    • A new inspection no longer copies last visit's readings. The prefill effect and its key-tracking code are removed, and choosing a hive clears fullness, as it already clears stores.
    • Each super shows "Not set" instead of "0%" until a reading exists, with "Last time 60% (12 Oct)" beneath when there was one. The previous-readings list carries its date for this.
    • Setting one super: see decision D3.
    • The save-time "non-number becomes 0" guard stays as a guard; the form can no longer produce one.

Decisions (all accepted as recommended, 04/11/2026)

  1. D1 – words for the other rating scales. The app already treats higher as better for all of these (selection scoring). Proposed:
    • Population strength: 1 = Very weak · 5 = Very strong
    • Temperament: 1 = Very defensive · 5 = Very gentle
    • Brood pattern: 1 = Very patchy · 5 = Solid
    • Recapping, VSH, SMR: 1 = Very low · 5 = Very high
    • Varroa (the disease rating): 1 = Minimal · 5 = Severe, as for the other diseases
  2. D2 – step ticks. A tick means "opened", not "done". Recommended: drop the tick and keep the step number on every step, with visited steps still shaded. Nothing then suggests a step is finished. The alternative is to keep the tick as it is.
  3. D3 – when one super is set, what are the others? The stored value is a list of numbers, with no "not set" option per super. Recommended: once one super is set, the others show 0% straight away, so what will be saved is visible, with the note "Supers you do not set are saved as 0%." The alternative is a database change allowing "not set" per super. That needs a design review and changes to the hive card, map and records readers, so it would not happen in WP04.

Not changed, and why

  • Queen seen / Eggs present cannot say "not checked": that is a new data state, which the plan says needs a design review first. The WP01 value table records the current meaning.
  • Stores dial seeding 50: noted by decision 3 as related but not decided. Ask if you want it handled the same way.
  • The other two-column rows in the secondary forms: WP06.

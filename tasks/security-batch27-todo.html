Batch 27: Irish Dates on the Server

Status: Implemented 23/10/2026, waiting for your test. This is Phase 2 fix batch 14. Two agents audited the edge functions and server code; I scanned the live database myself.

Most important: task reminders arrive an hour late all summer. The reminder e-mail function reads a task's time (say 10:00) as UTC, which is 11:00 in Irish summer time. Every reminder from late March to late October is about an hour late. Reminders set for less than an hour before a task arrive after the task has started. Winter is unaffected, and the clocks go back on Sunday (25/10).

A. Reminder and digest e-mails (edge functions)

New shared helper supabase/functions/_shared/dublin-time.ts. It gives today's Irish date, adds days to a date, and turns an Irish date and time into the real moment, handling summer time correctly.
Task reminders: the task time is read as Irish time, and the "today / tomorrow / this week" windows use the Irish date. The "daily" window covered 3 days instead of 2; it's fixed to 2. Reminders are compared in minutes, so a 30-minute reminder comes 30 minutes before the task, not after it starts. The "In N hours" text in the e-mail is right.
Weekly digest: "today" and the 7-day window use the Irish date. It's correct today only because it runs on Monday morning; this makes it correct whenever it runs.
Invitation and new-user e-mails: the expiry date and sign-up time are shown in Irish time (they were shown in UTC).
Deploy the 5 changed functions through MCP, with the same settings as now. Then check that the next reminder run succeeds in the function logs.

B. Database: "today" fill-ins

When the app sends no date, these fill in "today" using the database's UTC date, so between midnight and 1 am in summer they record yesterday:

  • Defaults on 6 date columns: order date, distribution date, nuc inspection date, queen weighing date, DCA observation date, wild colony observation date.
  • 8 database functions: paid date, queen failed date on hive archive, nuc status date, queen installed and mated dates, reared queen birth date, colony movement date, and the order date and its ORD-YYYY number.
Each one uses the Irish date instead: (now() AT TIME ZONE 'Europe/Dublin')::date, the same as the dashboard in batch 26. Only that word changes in each function; names, inputs and permissions stay the same. Saved as a migration file and applied through MCP; advisors checked.

Checked and left alone: the nuc emerged, set-up and mated timestamps are stored as plain dates (midnight UTC), so their date conversion is already correct.

C. App server code (smaller)

Shared helper: Mel's todayInDublin and addDaysISO move to src/lib/dublin-date.ts (Mel's tools keep working unchanged), plus one new helper for "midnight Irish time on this date".
Scale charts (BEEP and Wolf), custom date range: the range ran from 1 am to 1 am in summer, missing the first hour and adding an hour of the next day. It now runs midnight to midnight, Irish time.
Mel's varroa treatment check: a treatment exactly N days ago now counts as recent, matching the other tools.
Admin: the news article date and the export file name use the Irish date.

Not changed

  • The Vercel time zone setting stays as it is. Changing it would break code that relies on UTC; explicit Irish dates are safer.
  • The year look-ups (getFullYear) are only wrong on New Year's night, and Irish time equals UTC then.

Batch 29: Sign-in Redirects and Offline Sign-in

Status: Implemented 23/10/2026, waiting for your test. This is Phase 2 fix batch 16, covering C1-01, C1-02 and C1-03. Two agents traced every redirect path. There is no server middleware, so all redirects happen in the pages.

A. Invitation round trip (C1-01, C1-02)

What happens today when someone not signed in opens an invitation link:

Invitation page → /login?redirect=https://www.hivecraic.com/accept-invitation?id=… (a full web address) Login page only accepts paths starting with "/" → falls back to /dashboard → the invitee never gets back to Accept. With Google sign-in or a new account, the target is lost too.
One shared safety check, safeRedirectPath() in src/lib/safe-redirect.ts. It accepts only paths inside this app that start with one of /dashboard, /accept-invitation or /accept-rearing-group-invitation. It refuses other sites and the tricks used to sneak them in (//evil.com, back-slashes, hidden tabs). Everything else falls back to /dashboard.
Invitation pages (team and rearing group): send the page's path, not the full address.
Login page:
  • Checks the target with the shared helper.
  • If you're already signed in, it takes you straight to the target. Before, it sat on the login page.
  • Google sign-in and new-account confirmation e-mails carry the target through the sign-in callback (/auth/callback?next=…).
  • The old browser-stored pendingRedirect is removed. It was written in three places but never read, so it lingered and could fire later.
Sign-in callback: goes to the checked target, not always /dashboard. If sign-in fails there, the login page still remembers the target.
(Not done, see review.) Dashboard pages when signed out (for example a hive QR code scanned while signed out): the login link keeps the page you wanted, so you return there after signing in.

All four cases then work: an existing user with password, an existing user with Google, a new user with e-mail confirmation, and a new user with Google.

One setting to check (you, Supabase dashboard): Auth → URL Configuration → Redirect URLs. The live site already allows its own addresses, so https://www.hivecraic.com/auth/callback?next=… should work as it is. If you sign in on Vercel preview links or localhost, those need an entry too (e.g. http://localhost:3000/**). I can't see that screen from here.

B. Opening the app offline (C1-03)

The audit's cause was slightly wrong. The old offline fallback is dead code: it reads a storage key that the current Supabase library never writes. The real cause: once the hour-long sign-in token has expired and the phone is offline, the renewal fails with a "network" error. The app treated that as "signed out". After a 25–50 second wait it sent you to the login page, even though your sign-in was still valid.

A network error while renewing is now "can't check right now", not "signed out". The app remembers who was last signed in on this device (id and e-mail only) and keeps you in. Data loads simply fail while offline, as they do now. Back online, the session is checked and renewed as usual.
Same rule in getCurrentUserId(), so the 43 pages that use it no longer bounce you to login while offline, and on the home page (the app's start screen).
The dead offline fallback is removed. The remembered user is wiped on sign-out.

Security: the remembered id only decides which screen to show. The expired token is never used, and nothing can be read or saved without a valid session. A real sign-out (for example a password change elsewhere) still signs you out.

How you'll test

  • Invitation, signed out: open an invite link in a private window. Sign in with a password; you land on Accept. Repeat with Google.
  • New account from an invite: sign up from the invite; after confirming the e-mail you land on Accept.
  • Already signed in: open /login?redirect=/dashboard/hives; you go straight to Hives.
  • Unsafe link: /login?redirect=//example.com after sign-in goes to the dashboard, never the other site.
  • Offline (phone): leave the app for over an hour, switch to aeroplane mode and open it. You stay signed in (pages show they can't load), and back online it works normally.

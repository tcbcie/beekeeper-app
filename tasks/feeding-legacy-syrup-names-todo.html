Rename Legacy Syrup Feed Names

Problem

15 older feedings store the feed type without brackets, for example "Sugar Syrup 2:1" instead of the dropdown's "Sugar Syrup (2:1)". Because the text doesn't match a dropdown value exactly, the edit form treats them as custom Other types. They also show up as a separate type wherever feedings are grouped or filtered by type.

Findings (live DB)

Stored valueRename toRowsAccountsDates
Sugar Syrup 1:1Sugar Syrup (1:1)5117 Jul – 26 Sep 2025
Sugar Syrup 2:1Sugar Syrup (2:1)10121 Jul – 26 Sep 2025
  • These are the only syrup values outside the three dropdown options, with no whitespace or case variants.
  • The only trigger on feedings is feedings_updated_at, which bumps updated_at. Nothing in the app or in any DB function reads feedings.updated_at, so the bump is harmless.
  • No code change is needed. These all date from 2025, before the dropdown used bracketed names. Today's dropdown only produces bracketed values.

Plan (data only, no code)

Record the 15 row ids first (in the Review below) so the change can be reversed exactly.
One MCP migration, feedings_normalise_legacy_syrup_names, with two exact-match updates: 
UPDATE feedings SET feed_type = 'Sugar Syrup (1:1)' WHERE feed_type = 'Sugar Syrup 1:1';
UPDATE feedings SET feed_type = 'Sugar Syrup (2:1)' WHERE feed_type = 'Sugar Syrup 2:1';
Verify: no non-dropdown syrup values remain, and the bracketed totals rise by exactly 5 and 10.
Add a note to docs/features/feeding-syrup-3-2-inverted.md.
You open one of those 2025 feedings in Records → Edit. The dropdown should show "Sugar Syrup (2:1)", not "Other".
Untouched: syrup_inverted (stays false), quantities, dates, notes and other feed types.

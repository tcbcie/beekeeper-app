Save Button at the Bottom of Record Forms

Status: plan, awaiting approval  ·  Date: 29 October 2026

Your instruction: on the record screens (e.g. feeding, Varroa check) the Save button is only at the top, so on a phone the user has to scroll back up after filling everything in. Add a Save button at the bottom as well.

1. What I found

Each record form draws its own buttons; there is no shared shell. Four forms have the problem:

RecordFileSave today
Feedingsrc/components/records/forms/FeedingForm.tsxTop only
Varroa treatmentsrc/components/records/forms/VarroaTreatmentForm.tsxTop only
Varroa checksrc/components/records/forms/VarroaCheckForm.tsxTop only

Archive hiverecords/page.tsxAlready at the bottom — no change

In the four forms the Save and Cancel buttons sit in a header row above the <form> and reach it through form="feeding-form" etc. Saving runs through the form’s own handleSubmit and useSubmitLock, so a second button that submits the same form gets the same checks and the same double-tap lock for free.

The hive form (HiveFormSection.tsx) already has Save at the top and the bottom — the same pattern used here.

2. The change (same in all four forms)

Name the existing button group once and render it in both places, so the two can never drift apart:

const actions = (
  <div className="flex flex-col sm:flex-row gap-3 w-full sm:w-auto">
    <Button type="submit" form="feeding-form" ...>Save Feeding</Button>
    <Button type="button" onClick={onCancel} ...>Cancel</Button>
  </div>
)

// header row:            {actions}           (unchanged position)
// last child of <form>:  <div className="md:col-span-2">{actions}</div>
Phone ┌──────────────────────┐ │ Add feeding │ │ [ Save feeding ] │ <- existing │ [ Cancel ] │ │ Apiary ... │ │ Hive ... │ │ ... │ │ Notes ... │ │ [ Save feeding ] │ <- new, same button │ [ Cancel ] │ └──────────────────────┘ bottom nav bar (page already pads for it)
  • In the page flow, not a floating bar. A fixed bar would collide with Mel’s button, toasts and banners near the bottom edge. The dashboard layout already pads the page bottom for the nav bar and Mel, so the last button scrolls clear of both.
  • Same label, tone, 48px height, disabled while saving, and the same Cancel (with its unsaved-changes guard) as the top buttons.
  • md:col-span-2 because the forms are a two-column grid on wider screens.

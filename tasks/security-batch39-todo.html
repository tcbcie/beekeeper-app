Batch 39: App Shell

Status: Implemented 24/10/2026, waiting for your test. This is Phase 2 fix batch 26. It covers the open Medium findings in chunk 1: the app shell, sign-in, the installed app and offline use (C1-04 to 09, 11 to 14, 16, 18, 19, 23, 26, 27, 30). Three agents checked each finding against the code, and I re-checked the key lines. No database change.

A. Prompts and reminders: C1-04 to C1-07

C1-04, the update banner comes back after "Later": "Later" is saved for an hour, but coming back to the app (or the 30-minute check) shows the banner again within seconds. Now "Later" holds for the hour. Only the "Check for Updates" button ignores it, and a genuinely new update still shows.
C1-05, the notification banner comes back after "Later": on the Batches page the banner reappears on every visit, even after Later or ✕, because its 2-second timer runs after the check. Now the check comes first.
C1-06, notification permission asked without a tap: opening Batches pops up the browser's own permission prompt before you've seen why. One "Block" there is permanent. Now only the banner's "Enable" button asks.
C1-07, reminders pile up: each visit or save on Batches adds another 8 am reminder timer per event. Old ones keep their old details, so a deleted or re-dated batch can still remind you. Now old timers are cleared before new ones are set, and when you leave the page.

B. Offline storage: C1-08, C1-09

C1-08, the offline cache grows without limit: the app keeps a copy of every page and every page-data request. Next.js fetches page data for each visible link, with a changing code in the address, so the copies pile up. Offline, page data from an older version could also be served to newer code. Now page-data requests aren't stored, and the stored pages are capped at the 100 most recent. Your data from our own server and Supabase was already never stored.
C1-09, map tiles kept for ever: every map area you've looked at is kept, with no limit. On a full phone the browser can wipe all the app's offline storage, offline pages included. The map cache is now capped at the 1,500 most recent tiles.
Any change to the service worker file makes phones install the new version through the normal update banner. I won't touch the version number or the cache name; the old extra copies get trimmed as the app is used.

C. Sign-in and loading: C1-11 to C1-14, C1-16, C1-18

C1-11, one error breaks every page: if a page hits an error, the "Something went wrong" screen stays for every page you go to next, until you press "Try again" or reload. Now each page starts fresh.
C1-12, hourly sign-in refresh: mostly not real, because pages don't refetch. The one thing left is an extra account check every hour, which now runs only when the signed-in person actually changes.
C1-13, Back gets stuck: the installed app opens on the home address, which sends you on to the dashboard. That stays in the history, so pressing Back goes home, which sends you forward again. Now the redirect replaces the history entry, and the same is done on the login page.
C1-14, Enter signs in when you meant to sign up: on the login page, pressing Enter always triggers "Log in", even in sign-up mode, so a new user arriving from an invitation gets "Invalid login credentials". Now Enter submits in the mode you're in.
C1-16, reset-password page: in dark mode, a dark card sits on a bright yellow page, and the fields are about 40px tall. It now uses the same fields and background as the login page.
C1-18, duplicate requests on every load: the shell asks for your role three times and your subscription twice. Now one request is shared each time: the role through one in-flight request, and the subscription through the existing shared getter.

D. Screens: C1-19, C1-26, C1-27, C1-30

C1-19, warnings you can't read on a phone: the subscription warning in the top bar is a small coloured dot whose text only appears on hover. You can't do that on a phone, and it's a 20px target. It becomes a 48px button that takes you to your profile's subscription card. The hover text stays for desktop, and the profile-incomplete warning gets the same treatment.
C1-26, photo viewer: after zooming in on a phone you can't drag the photo around, because only a mouse drag works. Screen readers don't know it's a dialog, and Escape doesn't close it. Now touch dragging works, it's announced as an image viewer, Escape closes it, focus stays inside, and the hint mentions double-tap.
C1-27, American dates and wording: the renewal confirmation and subscription history show "October 24, 2026" and "expiration date". They become "24 October 2026" and "expiry". Admin's user and code screens get the same.
C1-30, offline notice covers Logout: while offline, the notice sits over the top-right of the bar, on top of Logout, and can't be dismissed. It moves just below the bar.

E. Closed without a change

C1-23, theme hydration mismatch: not real today. The no-flash script sets the theme before the page appears, and the only component that shows the theme is never in the server-rendered page. I'll note it in the register.

Type-check, lint and the whole test suite; short tests for "Later" on the update banner, Enter on the login page and clearing reminder timers; the qa-engineer audit.

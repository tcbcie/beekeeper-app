Security Batch 9: Browser Hardening (CLI-03 to CLI-08)

Status: Step 1 done 17/10/2026; tested by you, committed and pushed. Step 2 (enforce the CSP) follows after a few days of reports. Findings: the client and PWA Low findings from Phase 1.

What's open

IDProblem
CLI-03No Content Security Policy on the app (only /embed has one, for framing). Sign-in tokens live in browser storage, so a CSP is the main brake on token theft if a script-injection bug ever slips in.
CLI-04No Permissions-Policy header. The server announces "X-Powered-By: Next.js". The bare hivecraic.com sends a shorter HSTS header than www; that is a Vercel domain setting, not code.
CLI-05Open redirect after login. /login?redirect=/%09/evil.com passes the check, and the browser turns it into //evil.com. So a just-signed-in user could be sent to a look-alike phishing page.
CLI-06Exact coordinates in the public trace functions. Already fixed in batch 6 (DB-04); it only needs marking as closed.
CLI-07The hive QR print window inserts the tag code without escaping it. The codes are system-generated, so this is hygiene only.
CLI-08The TCBC embed widget loads Chart.js from a CDN with no integrity check. A tampered CDN copy would run on tcbc.ie.

Plan

A. CSP in two steps (so nothing breaks for users)

Step 1 (this batch): add the CSP as Content-Security-Policy-Report-Only in next.config.ts. The browser enforces nothing yet and reports anything that would be blocked to a small new route, /api/csp-report. That route writes one short line per report to the Vercel logs, with a capped size and no query strings.
Step 2 (a follow-up, after a few days of normal use): I read the reports from the Vercel logs, add anything legitimate I missed, and switch the header to enforcing. That's a one-line change.
default-src 'self';
script-src 'self' 'unsafe-inline';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https:;
font-src 'self' data:;
connect-src 'self' https://<project>.supabase.co wss://<project>.supabase.co
  https://api.mapbox.com https://events.mapbox.com https://*.tiles.mapbox.com
  https://api.open-meteo.com https://archive-api.open-meteo.com
  https://nominatim.openstreetmap.org https://api.postcodes.io https://en.wikipedia.org;
worker-src 'self' blob:; child-src blob:; media-src 'self' blob:;
manifest-src 'self'; frame-src 'none'; object-src 'none';
base-uri 'self'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests

I re-checked every external address the browser code calls today; the list above covers them. Stripe, BEEP, Wolf, Resend and Google Geocoding are only reached from the server or by full-page navigation. 'unsafe-inline' for scripts is needed by Next.js and the theme script. Removing it needs per-request nonces, which is a bigger change and not worth it yet. /embed keeps its own framing policy.

B. Other headers (CLI-04)

Permissions-Policy: camera=(self), microphone=(self), geolocation=(self), payment=(), usb=(), browsing-topics=(). The microphone is for voice notes, geolocation for apiary location, and the camera for photos.
poweredByHeader: false, so the server stops announcing the framework.

C. Small fixes (CLI-05, CLI-07, CLI-08)

CLI-05: the login redirect is parsed as a URL and accepted only if it stays on our own site; then just its path is used. Tabs, backslashes and encoded tricks all fall back to /dashboard.
CLI-07: escape the tag code in the QR print window, the same way the hive number already is.
CLI-08: the widget loads the published chart.umd.js (byte-for-byte the npm 4.4.1 file; the .min.js it used is generated on the fly by the CDN, so it can't be pinned safely) with integrity="sha384-dug+Jx…" and crossorigin="anonymous". The browser refuses a tampered copy.

Batch 45: API Routes

Status: Implemented 29/10/2026, waiting for your test. This is Phase 2 fix batch 32. It covers the open findings in chunk 2 (API routes and e-mail functions): C2-05 to C2-09, C2-11 to C2-14, C2-16, C2-17 and C2-30. Three agents checked each finding against the code and the live database (counts only). Two e-mail functions need redeploying; no table changes.

A. Scales: C2-05 to C2-08

C2-05, Wolf's "previous 24 hours" is always blank: it asks Wolf for one reading per day over exactly one day, so it never gets the two readings it needs. Also, the "last 24 hours" figure is really the last hour's change. One hourly fetch covering the last 48 hours now gives both figures properly.
C2-06 / C2-07, too many calls to BEEP and Wolf: opening a BEEP hive's scale makes 15 calls to BEEP, and each period change makes 8 more. A Wolf hive makes 9 calls one after another. The history chart only needs the history, but it gets the full summary too.
  • When a chart asks for a period, the route now returns just the history.
  • BEEP: 15 calls go down to 8 on opening, and 1 per period change.
  • Wolf chart: 9 calls go down to 1.
  • No screen changes are needed.
Merging the summary calls further belongs in the performance batch, after a check that BEEP doesn't thin out 60 days of data.
C2-08, custom dates aren't checked on the server: a mistyped date gives a server error, but only after 7 or 8 calls to the scale maker. A back-to-front range gives an empty chart. Ten years asks for about 87,600 hourly readings. The route now refuses a bad date, a back-to-front range or more than a year with a clear message, before calling anyone. Wolf ranges over a month use daily readings.
C2-09, time limit: Vercel now gives every route 5 minutes, so only the Wolf route needs its own cap. It makes calls one after another with retries, so a hanging Wolf server could keep it running (and billing) for the full 5 minutes. The cap is 90 seconds.
Small: scale IDs are encoded in the browser's request address.

B. Calls that can hang: C2-12, C2-13

E-mails have no time limit: all 7 places that send e-mail through Resend wait for ever. The task reminders and the weekly digest send one e-mail at a time, so one stuck e-mail stops everyone after it from getting theirs. Each send now gives up after 10 seconds (20 for the invoice with its PDF).
The clock stops too early: for BEEP, Wolf, the batch elevation lookup and the GDD embed's weather call, the time limit stops once the reply starts arriving, so a reply that trickles in slowly can hang. The time limit now covers reading the whole reply.

C. Bad requests: C2-14

A garbled request gets "server error": 7 routes answer it with a 500, and the BEEP connect route says "Check your email and password". These are impersonation, the knowledge base (2), news (2), user role and Wolf connect. One shared helper now answers "Malformed request body" (400).

D. Shared database client: C2-16

Mel's knowledge and news searches build a new admin database client on every call. The storage clean-up job and the Stripe webhook each build their own. All three now use the shared one, as the batch 20 rule says.

E. The complete export: C2-11

It can't work today: the admin "complete" export builds the whole file in memory and sends it in one go. Mel's knowledge base alone is about 103 MB as text, so the file is about 110 MB. Vercel refuses replies over 4.5 MB sent in one go. The admin log shows it has never been run since logging started, which is why nobody noticed. The "empty schema + admin" export is small and works.
Decision 1: the complete export. Done: streamed (you approved). The file is sent table by table as it's built. Please run it once to confirm Vercel lets it through; if it doesn't, the fallback is to remove the "complete" option.

F. Knowledge base: C2-17

The database already deletes a source's chunks with it, and today there are 0 orphans. Three gaps remain:
  • The chunk count after an upload ignores errors. One source shows 0 chunks but has 19.
  • Deleting a single chunk never lowers the count.
  • If deleting a news article's knowledge source fails, the article is deleted anyway and its text still feeds Mel.
Each is checked or recounted now, and the article stays if its source can't be removed.
Decision 2: one data fix. Set the chunk count of the one source that says 0 but has 19 chunks (added on 30/12/2025 by the local upload script). It's a single update to one row. Done (you approved): exactly one row changed, now 19. The upload script already checked its error, so it needed no change.

G. E-mail links: C2-30

The "change your settings" links in the task reminder e-mail and the weekly digest point at the Supabase server, not HiveCraic, so they lead nowhere. They now go to https://www.hivecraic.com/dashboard/profile and /dashboard/batches, as the invitation e-mails already do. Both functions get redeployed.
I also confirmed that the security fix from batch 13 (C2-31) is in place: every e-mail escapes the user's own text, including the deployed digest.

Batch 34: Traceability and Orders

Status: Implemented 23/10/2026, waiting for your test. This is Phase 2 fix batch 21. It covers the open Medium findings in honey traceability (C8b-03, C8b-04, C8b-09 to C8b-13) and CRM orders (C8b-05, C8b-06, C8b-08). It also fixes one new bug the checks found: harvests saved with a blank unit. Three agents checked the code and the live database. The next batch covers records and hives (batch 35).

A. Weights and origin percentages: C8b-12, C8b-13, C8b-04

C8b-12, editing a jar batch overwrites its total: opening a batch to edit it recalculates its total weight from the whole of its containers. So a batch that used 12 kg of a 25 kg bucket becomes 25 kg on any save. Now the total is only recalculated when you tick or untick a container.
Each harvest counted once, and in kg: when a batch uses several buckets filled from the same harvest, that harvest is counted once per bucket. Pounds are also added as if they were kilograms.
  • Where: the batch preview, the public trace page (the QR code on the jar) and Mel's traceability answers.
  • The fix: one shared lb→kg helper, used everywhere, and each harvest counted once per batch.
  • The public page: its database function is corrected, with the same results format and the same public access.
Today no published percentage changes, because only one batch draws on two apiaries. This stops future ones from being wrong.
Container "Used / Remaining": today, every container in a multi-container batch is charged the batch's whole total. Now each container is charged its share of the batch total, in proportion to its weight, never more than it holds, and rounded to 2 decimals. Single-container batches are unchanged.
New: harvests saved with a blank unit. A new harvest starts with no unit. The form shows "kg", but saves a blank. This affects 62 harvests.
  • New harvests now start as kg.
  • A one-off database update sets those 62 blank units to "kg". That is what the form showed, and what every calculation already assumed.

B. Creating batches, containers and jar sales: C8b-09, C8b-10, C8b-11, C8b-04, C8b-03

Lot number and trace code:
  • If the lot number can't be generated, the save stops with a message. Before, it fell back to "…-001", which clashes with an existing batch.
  • A failed trace code is reported clearly instead of as a database error.
Half-made batches and containers: if linking a new batch to its containers and jars fails, the new batch is removed, so a retry doesn't create a second batch under the next lot number. The same applies to new containers whose harvest links fail. The container form also gets the double-tap lock the other forms have.
Jar sales recorded twice: on a weak signal at a market, the sale can save but the reply get lost. Pressing Save again then added a second income row. Now each sale window has its own fixed record id, so a repeat save can't make a second row. It also gets the shared double-tap lock.

C. CRM orders: C8b-05, C8b-06, C8b-08

C8b-05, unsaved item edits lost: if you change the items and then press Mark Paid, Record payment, Apply credit, Fulfil or Cancel, the order reloads and your changes vanish. Payment is also booked at the old total. Now those actions are refused while there are unsaved changes, with "Save your item changes first".
C8b-06, items that failed to load: today the editor shows "No items yet". Saving after re-entering one line then deletes all the real lines. Now it shows an error and hides the editor and Save until the page is reloaded.
C8b-08, cleared number fields: clearing a quantity or price used to snap it to 0. The line was then silently dropped, or saved at €0. Now the field can be left empty while you type, and saving asks you to fill in every quantity and price instead of dropping lines. Negative prices are stopped as you type.
Database changes: one migration, applied through MCP and saved in supabase/migrations/. It corrects the public trace page function and sets the 62 blank harvest units to "kg". I'll run the security advisors afterwards and check the public page still returns the same results format.

Finishing

Type-check, lint and the whole test suite; a short test for the lb→kg helper; the qa-engineer audit.
Docs: docs/features/traceability-orders-batch34-plan.md, honey-traceability.md, the Phase 2 register and memory.
You:
  1. Edit a jar batch and change only its story: the total weight stays as saved.
  2. Scan a jar's QR code: the trace page shows the same origins as before.
  3. In an order, change an item and press Mark Paid: you're asked to save first. Clear a price and save: you're asked to fill it in.
  4. Record a jar sale: it appears once in Profit & Loss.

Batch 28: Remaining High Findings (Data Correctness)

Status: Implemented 23/10/2026, waiting for your test. This is Phase 2 fix batch 15. Three agents confirmed each item is still open, and the key facts were checked live. The sign-in redirects (C1-01 to C1-03), the community map (C7a-01, C7a-05), the small tap targets and the tooling follow in later batches.

A. Hive list and records

C3-01, hive cards losing data past 1,000 records. The hive list loads every inspection, treatment, check, feeding and harvest for all your hives in one request, and Supabase stops at 1,000 rows. Nobody is over today: the biggest account sees 560 inspections. Past about 85 hives the oldest hives' cards would show "Never" and lose queen, eggs and super data. Fix: read these in pages (all rows, in a stable order) and in groups of 100 hives, using one shared helper. No database change; results stay exact.
C3-02, ownership filter race. Changing My / Team / All loaded twice, the first time with the old filter. Whichever finished last won, so "Team" could show your own hives. Fix: one load per change, and an older load can no longer overwrite a newer one.
C4-02, shared-hive link on Records. Opening a team-mate's hive from a link switched the filter to "All" mid-load. The "already loading" guard threw that second load away, so the list stayed empty. Fix: the guard remembers the latest dropped request and runs it straight after.

B. Teams and admin

C6-01: after deleting a team, removing a member or leaving, the team-access memory is cleared, as sharing already does. Before, the old team view stayed for up to 30 seconds.
C6-02: Remove and Unshare refresh the team the row belongs to; before, it was whichever team was last opened for a modal, sometimes another team's data. A second press that removes nothing says "already removed" instead of "removed".
C6-03, rearing group ownership transfer: it was three separate updates from the browser, so a dropped connection could leave two owners. Fix: one database function that does all three or none. It checks that you're the owner and the new owner is a member. Signed-in users only, saved as a migration, advisors checked.
C9a-03, impersonation: the admin's saved session is only stored once the sign-in as the user succeeds. A failed attempt no longer leaves a false "Impersonating" banner and a stored token behind.

C. Reminders, research and the knowledge base

C2-01, reminder e-mails: the function re-read every pending task once per user, so the work grew as users × tasks. Fix: read once per reminder frequency (2 today), and mark reminders sent once at the end. Redeploy and check the logs.
Decided (C2-04): A, remove the broken branch. The reminder function has a branch meant to remind team members about tasks on shared hives. It has never worked: it reads a table and a hive column that don't exist (checked live), so only the task's creator is ever reminded.
A (recommended now): remove the broken branch. Nothing changes for anyone.
B: build team reminders properly (members of a team the hive's apiary is shared with). This is a new feature: more people would get e-mails. Better as its own small batch.
C7b-03, Research → Foraging hours: deselecting the last year during a load no longer leaves the spinner running for ever.
C8a-03, Tools → Varroa weather: changing apiary no longer reloads the whole tool. A slow forecast for the previous apiary can no longer replace the new one.
C2-02, admin knowledge base and news uploads: each chunk was one AI call and one save, one after another, so large PDFs timed out half-loaded with a count of 0. Fix: the AI calls are made in batches of 100, with one save for all chunks and a longer time limit. A failed upload removes its half-made source.

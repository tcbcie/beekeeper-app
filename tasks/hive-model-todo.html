Hive model: system, make, material and photo per hive

Full plan: docs/features/hive-model-plan.md. Status: decisions made (photo on both model and hive; Type label stays; all 5 phases). Built; waiting for you to test.

Idea in one line

Describe each kind of equipment once as a hive model (for example "Abelo poly National" or "Payne's poly nuc", with a photo), then pick the model for each hive. The hive card, hive page and apiary visit then show what is in use and which frames to bring.

Review

Built as planned across all five phases. Differences from the plan:

  • The hive form picker sits inside the form rather than in its own component.
  • Admins retire a hive system instead of deleting it.
  • The visit checklist shows the models of the hives that have tasks.

What a user sees

  • Profile, then My hive models: add a model with name, system, size, make (with suggestions), material, frames per box, photo and notes. Each row shows how many hives use the model.
  • Hive form: a Hive model picker at the top of Hive configuration. On a new hive, picking a model fills in the size and frames per box. There is also an optional Hive photo. A team-mate sees the model but cannot change it.
  • Hive card: the model name and its system, make and material, with a photo thumbnail that enlarges on tap. The hive's own photo is shown, or the model's if the hive has none.
  • Hive page: the model, frame size, frames per box, model notes and the photo, under Hive information.
  • Hives list, selection bar: a Hive model action sets or clears the model on all the selected hives.
  • Apiary page and visit checklist: "Hive models here", for example "6 × Abelo poly National", plus the brood frame sizes needed.
  • Settings, then Hive systems (admin): edit systems, their frame sizes and default frames, or retire a system.

Database

New tables hive_systems (9 seeded) and hive_models, plus hives.hive_model_id and hives.image_url. The database rules were tested in a rolled-back transaction:

  • a hive uses only its owner's models
  • duplicate names are refused
  • deleting a model clears it from its hives
  • a removed photo is queued for cleanup
  • other users cannot see a model that isn't on a hive they share

QA audit fixes

  • When a load failed offline, the saved copy of the models could be ignored. It is now shown.
  • Editing a hive re-sent an unchanged model id. A stale id (from a model deleted elsewhere) would then fail the whole save. The id is now sent only when it changed.
  • The summary heading id is now unique, and the photo field heading is no longer an empty <label>.
